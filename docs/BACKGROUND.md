# 为什么需要 context-kit

复杂协作的状态往往散在多个会话中：目标改过、方案否决过、实验跑完但没人回收、另一个会话发来的事项没有处理。聊天摘要能帮助回忆，却不一定能指出当前有效的方案和责任人。

一个案可以跨多个会话；会话只是当前执行载体。用户说目标、询问进展、作出必要决策，工具负责整理可以核验的工作记录。

## 三个目标

1. 可接手：下一会话能找到目标、当前方案、否决理由、证据、未决问题和下一步。
2. 可协作：一个案有明确持笔，执行任务有边界，来件有处理结果。
3. 可核验：完成、已测试、推测、未测分别记录；遗漏和失败如实保留。

## 方法与依据分开

任务板、案、持笔、收件位不依赖模型计价。会话改名、消息投递、状态查询、压缩、缓存统计则依赖平台与实际工具。

- [Claude 证据](../claude/EVIDENCE.md)：保留 2026-08 样本、计价口径、试点与盲区。属于历史报告，本次迁移没有重跑原始实验。
- [Codex 证据](../codex/EVIDENCE.md)：公开资料确认到哪里、哪些假设尚待真实复杂任务审核。

缓存优惠不等于 takeover 一定划算；窗口装得下也不等于任意任务都同样可靠。经济收益与质量应分别审核，不能拿成本阈值解释性能拐点。

## 使用范围

多轮设计、实验、排障及多会话协作是主要场景。复杂项目中的小改可直接完成并关联已有任务，不为每个动作再建案。已有任务板、ADR、Issue 或交付目录应优先复用。

成功的判断是接手能继续正确工作、来件不漏、结论能追到证据。结构检查只能证明文件可读、包可搬移，不能替代真实协作验收。
