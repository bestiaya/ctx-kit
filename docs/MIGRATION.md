## 明确调整的协作行为

- 身份与名称分开；名称变化不产生新案或新任务。
- 命名采用当前核对的 Claude 实现：案号＋任期号、派发者子号、散活登记行号；只在共用方法维护。运行中的旧名保留，新任期使用新格式。
- 保留 A–I 语义，新模板把业务状态和交接状态分开。
- 执行者不并发改同一案的 E 行，交独立结果，由持笔回填。
- 接手必读 H、I 与离线来件，不凭空闲/时间戳接管。
- 不补写用户没提出的验收数字；无阻塞时不强制等待抽查。
- Claude 费用纪律保留在平台层，Codex 不继承用量阈值、禁 compact 或按用量强制交接的规则；交接实际完成后的会话退役标记按[共用规则](METHOD.md#交接后的会话退役标记)执行。
- 原“必 push”及后台清理依赖目标项目既有授权，不由安装包全局启用。

## 安装升级

旧的 `cp -R 03-setup/skills/ctx-* ...` 不再适用。源码入口引用共用资源，须先打包成自足 skill 再安装。检查项目级和用户级同名技能，备份或选择唯一生效位置，避免两版同时加载。

外部文档、用户自己保存的绝对路径和旧 hook 配置不会自动修改；明确升级该安装时再更新。

## 2026-10-15 案头与记录文件分开、接手阅读预算

案改为案头加三份记录文件（决策、实验、过程），九节名与语义不变，只改所在文件：案头只放当前推进状态与未结事项，目标 10,000 字符、15,000 整理线；接手到第一个实际动作的阅读合计 30,000 字符以内，均按 Unicode 字符计。接手先比来件 ID 再开新件，记录文件按下一步定点读；交接时把已结内容移入记录文件并写继任阅读表，案头字符数记入交接回执。原“案头+A–D 10,000 绿线、15,000 瘦身线”改为历史口径。旧的单文件案照常可读，不强制改历史；超线案由持笔拆分。新增 `templates/CASE-RECORDS.md`，随包自动纳入；检查脚本未加，规则跑通后再定。

## 2026-10-08 结案与终止

本机 Claude `ctx-handoff` §2C 已有 closed 分支，原因包括完成、放弃、并入其他案；原共享版本只保留了交接，本次补齐这部分并扩展共同的结案类型和处置记录。五个现有技能共用 METHOD 与 `workflows/case-lifecycle.md`，不新增终止技能或必记子命令。

status 默认仅展开并统计活跃案，历史按需查看，终态仍检查并报告收尾异常；kickoff 不自动复用终态案，takeover 在明确恢复后才认领，checkup 审核全部范围内的案。终止保留证据和未验证事实，不删除文件、不复用案号。结束案仍在同一索引表，状态/持笔是案头投影。

旧 closed/已收口等终态缺类型时按已结束、类型未知读取，不批量改旧案或猜测完成。新增结案字段与处置表按实际处理补齐。Claude 现行安装可能还有未迁入共享层的其他能力；生成新包不等于覆盖了该安装，替换前须保存并审查本地差异。

## 2026-10-07 命名来源校正

此前迁移使用 Git `71d3b4c129079cc779875be726471438029341dd` 中的旧技能，其取号是项目内最大会话号加一。此次直接核对本机已安装的 Claude `ctx-kickoff` §2/§3、`ctx-takeover` §3：它们已改用案头 `stint`，并明确禁止为了取号查询会话列表。不能再将旧快照统称为现行原版。

共享 METHOD、工作流、模板和两端平台说明已按该行为校正。平台只负责标题/身份工具，规则在共享层；安装包中的 references 是构建副本，不是另一份可独立维护的设计。

- 新案 `任期：01`；正式继任递增。旧案无字段时由下一次正式接手初始化为 01，早先历史保留在编年；同一持笔重试不递增。
- 板的名称列保存案短名，持笔列作为案头镜像；旧板由持笔在维护本案时补齐需要的列，不能借升级覆盖别人的状态。
- 散活仍依据板上行号命名；为兼容后续整理，模板显式保存首次登记行号，保留已有号，不因排序或归档重新分配。此列是本次适配的显式记录方式。
- 已存在的旧标题、用户指定标题和已派名继续有效；不从标题倒推出任期，不批量改名。派生编号由派发者分配，只有实际派出的执行会话带 `-exec`。
- 保留现有并发约束：执行者不直接并发写案，交付后由持笔回填载体；这与 Claude 旧条文中执行者直接写 E 的操作方式不同，命名语义相同。
- 正式业务案的字段迁移由原持笔处理，安装新版技能本身不接管案或自动修正所有历史记录。
- 本轮补清重试与写入边界：仍在持笔的同任期重试不加号，释放后再次认领递增；派生预留号与散活归档号保留占号记录；部分同步按原任期补写。这些是共用流程的防重和并发约束，不冒称 Claude 源已有逐条实现或已通过真实会话验收。
