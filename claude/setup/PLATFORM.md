# Claude 平台规则

先执行共用工作流；此文件保留 Claude 工具与旧经济策略的差异。历史依据见 [EVIDENCE](../EVIDENCE.md)，不推广为 Codex 的规则。

## 身份、技能与辅助工具

- 在支持的客户端选择 `/ctx-kickoff` 等技能；先发现可用工具。若有 `set_session_title` 或等价标题工具，按 [共用会话命名](../../docs/METHOD.md#会话命名) 设置标题；失败报告 UI 未同步。
- 编号、短名、旧名兼容与派生规则只按共用方法，从案头任期、板上散活登记行号或已派记录取得。禁止为取号调用 `list_sessions` 或扫描会话历史；列表仅用于核实身份、状态与地址。标题成功后按实际返回的会话 ID 定点回读，并同步案头和板的持笔镜像。
- 持笔使用 `claude + 完整会话 ID + 名称`。拿不到 ID 如实标注，不以最近 JSONL 或相似标题冒充。
- 原 digest agent 与 PreCompact hook 保留。digest 是可选读料工具；委派服从当前授权与工具能力。hook 只提醒保存状态，不等于已保存或已阻止压缩。
- 原缓存脚本只适用于历史 Claude JSONL 口径。打包后在 ctx-checkup 内为 `scripts/cache-audit.py`；源码位置为本目录 `scripts/cache-audit.py`。使用环境中可工作的 Python 3.9+，不硬编码某台机器解释器。
- 在目标项目 cwd 执行 `python3 <脚本绝对路径> --all`；会话档案目录不匹配时用 `--project <Claude项目档案目录>`。该参数指日志目录，不是代码项目目录。先验证路径与授权范围。

## 原策略保留范围

下列是 2026-08 原实现的操作口径，仅在目标项目已采用且模型/计费环境适用时继续使用；新安装先核对，不把历史数字作为当前厂商保证。

| 原策略 | 沿用时的含义与限制 |
|---|---|
| 执行 150–200k 黄线，200k 红线；讨论批次结束交接 | 经济经验线，不是质量拐点 |
| >1h 按冷回访做预算 | 样本有例外，不证明每次实际全量未命中 |
| input×1 + read×0.1 + write×2 + output×5 | 历史当量，不是当前账单；不含所有 compact 和子代理成本 |
| >30k 一次性材料可交 digest | 当时的读料策略，工作集不受此限；不替代当前委派授权 |
| 讨论避免 compact，执行临近窗口才作急救 | 历史操作策略；当前用户要求或平台自动行为优先，如实记录 |
| 收口后加 ✕、提醒新会话接手 | 交接保存核验并释放后必须按共用退役标记规则执行；不是按需采用的历史策略 |
| 收口 commit/push | 只在目标项目已授权的范围沿用；只加入本轮路径，失败如实报 |

## 交接后的会话标记

交接分支必须执行[共用退役标记规则](../../docs/METHOD.md#交接后的会话退役标记)。从交接记录定位交出的旧会话及原标题；若当前客户端提供 `set_session_title` 或等价标题能力，按实际接口添加一次 `✕ ` 并在可用时定点回读，已有前缀不重复添加。不得猜造工具或改内部会话存储。

缺少改名能力或执行失败时，记录“UI 标记未完成”及原因，与文件交接/释放结果分别报告；不能把给用户的操作提示当作成功。重试不修改继任持笔或案板。原会话仍可响应后续请求，需要重新持笔时执行正式接手。其余删除、归档、关闭或创建聊天等动作不由退役标记触发。

## Claude 周检

先记录真实时间，核对案、载体与授权范围，再运行历史脚本。重写占比 <10%、讨论 p50 <150k、执行 compact=0/峰值<200k 是历史策略；表中警告只是筛查，不据此认定模型质量失败或自动退役。

案头+A–D 的 10,000 字符绿线、15,000 瘦身线取代早期文档互相冲突的 7,000 字符线，仅为沿用旧项目的阅读预算。需要瘦身时保留历史与指针，不能删除未解决事项。更短也不自动意味着交接成功。

档案归属优先准确会话 ID，再核验元数据；无法确认保留未知，不用收口日期附近的账单猜唯一匹配。旧周检“自动补退役标记”改为只报告候选，获得目标会话清理授权后再执行，避免误伤活任务。

## 案生命周期

结案、终止、合并和恢复只执行[共用生命周期](../../workflows/case-lifecycle.md)，状态判定与收尾规则不在平台层另定义。案已结束不代表平台聊天已归档或进程已停止；需要核验实际载体时使用本平台已知 ID 与可用工具。用户只要求结束案时，不自动退役当前聊天；标题、归档、进程与跨会话消息分别按实际授权和工具结果记录。

## 方案送审

- `/ctx-review` 或自然语言按[共用送审流程](../../workflows/review.md)分清角色。收到自足请求或 stdin 材料时直接评议，不必加载整套流程；CLI 审核输出正文，调用方原样保存回执和运行记录。人工文件审核只写指定回执，不接管原案。
- 聚焦目标、整体判断和实质异议；引用作为背景，不默认逐链接核验，不重复调用方的版本、身份检查。只有会改变结论的具体事实疑点才定点核对，未知如实标明。
- 调用方按[CLI 调用约定](../../workflows/review-cli.md)管理执行和次数。用户选择 Desktop 人工审核时核对实际项目与允许写入位置，不改变权限设置；旧审核入口冲突无法消解时报告，不擅自清理。讨论结果经用户确认后再改文件。
