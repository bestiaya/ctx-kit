# Codex 依据与待审核事项

资料核对日期：2026-10-04。以下区分公开机制、有限研究、推论与本项目真实任务验证。本版未进行复杂任务成本/质量对照实验。

## 已知与边界

| 事项 | 资料支持到哪里 | 不能推出什么 |
|---|---|---|
| 缓存优惠 | 官方 Codex credits 区分普通输入与缓存输入，且没有单独缓存写入费；API-key 使用另一套 API 价格 | credits 价格不能直接推算订阅内额度；Claude 写价公式不能套用 |
| 缓存保留 | API 文档中 GPT-5.6 及之后模型最低保留策略为最近写入/复用后 30 分钟，可更久；早期模型不同 | 不证明当前 Codex 客户端实际 TTL；不是过一小时必冷 |
| takeover | 缩小下一请求携带的上下文，可能降低后续处理成本（机制推论） | 新会话也会冷却，不能把交接当防止过期；要计入交接和补读返工 |
| 长上下文质量 | 外部研究对 GPT-4.1/o3 等及特定 GPT-5 任务观察到退化 | 不证明当前 GPT-6、复杂协作或统一 50% 分界 |
| 本项目实施情况 | 提供共享工作流、Codex 工具适配、可搬移打包与审核模板 | 静态检查不证明真实交接质量或经济净收益 |

资料：

- [OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)：模型相关的缓存机制；不能由闲置时长单独断言本次全量未命中。
- [Codex pricing](https://learn.chatgpt.com/docs/pricing)：计费渠道和缓存优惠，实际价格需使用审计当日版本。
- [Chroma Context Rot](https://www.trychroma.com/research/context-rot)：18 个模型的长输入与干扰实验，包含较早 GPT，未验证当前 GPT-6。
- [GPT-5 vs Other LLMs in Long Short-Context Performance](https://arxiv.org/abs/2602.14188)：特定大量短文本任务；不能泛化为全部 GPT 的窗口百分比阈值。

## Q1：缓存冷却是否值得主动 takeover

状态：**待本项目真实复杂任务确认**。

候选观察条件：约 500k 当前上下文、较长间隔（例如一小时）、任务阶段断点。它们是采样条件，均不是触发规则。

对比原会话继续与新会话加载交接材料继续，记录模型/客户端/计费方式、当前上下文、间隔、实际缓存命中、输入输出、时延、交接生成与接手成本、补读返工、压缩和子任务开销。区分实际请求输入与会话历史总长。

只有总收益可比较、交接质量未明显损失、样本及反例可复核时才建议阈值。看不到费用或订阅映射时只报可观测量；无法对照则判不出，不发无意义请求为旧缓存“保温”。

## Q2：超过窗口 50% 后是否出现质量下降

状态：**有一般风险依据，具体模型/任务/阈值待确认**。

固定模型与主要配置，记录实际可用窗口及当前输入（未知则不算占比），在不同阶段核验早期约束、当前决策、事实召回、推理与交付质量。使用执行前确定的判据和原始证据；条件允许时盲评。

区分任务难度、过时/矛盾方案、信息位置、压缩、交接整理效果。累计 token 超过窗口不代表当前上下文超过窗口；模型、服务端或客户端变化后，旧结论不自动沿用。

## 怎么回填

形成真实复杂任务样本后，由 `ctx-checkup` 按 [审核模板](../templates/AUDIT.md) 将完整报告写在目标项目。这里仅在获准维护工具包且证据充分时登记可复核结论：时间、平台/模型、样本范围、结论、限制、报告路径。

当前审核记录：尚无本地对照结果。**不自动按 500k、一小时或 50% 收口，不禁用原生 compact。** 不建立定时任务或后台采集器。
