# 合入目标项目 AGENTS.md 的片段

仅合入下面代码块，保留原有指令。源方法在工具包；安装后的细节由技能按需读取。

```markdown
## context-kit 协作
- 复杂协作工作使用任务板、案文件、持笔和收件位；按当前项目/子项目范围定位，优先复用已有记录。小动作归入已有任务。
- 开工用 ctx-kickoff，查进展用 ctx-status，交接/接手用 ctx-handoff / ctx-takeover，协作与上下文检查用 ctx-checkup；方案送审与意见回收用 ctx-review（例如 to claude，完成后说“审核好了”）。
- 用户可直接说“这个案不用了/终止 C-07/并入 C-14”，由 ctx-handoff 走共用结案流程；说“重新做 C-07”由 ctx-takeover 恢复。无需新增技能或必记子命令。ctx-status 默认展开活跃案，历史按需查看，收尾异常始终报告。
- 面向实践的方法说明使用 ctx-method-doc，按文档用途选择主线；普通 README、案卷、短邮件和纯数据报告不自动套用。
- 当前决策、方案、交付证据及时落盘；一个案一位持笔，执行会话写独立交付件，持笔回填。接手必须检查 H 缺口、I 收件与未合并来件。
- 命名遵循共享 METHOD，编号与标题内容间使用全角竖线 `｜`：案内用案号＋案头任期，散活用板上登记行号，派生子号由派发者分配；不查会话列表取号。用户指定名和运行中的旧名保留，只有派出的执行会话加 -exec。持笔记录平台与稳定 ID，成功改名后同步案头及板上持笔镜像。
- 按用户已授权的协调范围派活和投递；记录已准备、已派出、已接收、已完成的区别。未明确要求时不自动新建/归档聊天或提交推送。
- 500k、一小时、50% 均为待验证条件，不作为自动交接阈值；允许原生压缩。复杂任务样本形成后，分别审核缓存/交接整体开销和上下文质量，不把 API 价格当订阅额度。
```
