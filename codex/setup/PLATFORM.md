# Codex 平台适配

本文件补充共用流程，不能把桌面工具的存在假定为所有 CLI/IDE 都具备。先发现当前可调用工具，再用其实际参数。下列名称是能力名，可能带 MCP 前缀；不要臆造调用。

## 当前会话、身份与命名

- 当前聊天改名用 `set_thread_title`，省略 `threadId` 即目标为当前聊天。只有成功返回才报改名完成；返回的 ID 可用于当前持笔。不要为取得 ID 反复改名，也不要从“最近聊天”猜当前身份。
- 已知 ID 时用 `read_thread`/`list_threads` 核对标题、项目和状态，使用工具返回标题原文。列表可能含别的项目，定位时必须同时核对项目路径与 ID；多主机场景同时保存工具返回的 hostId，后续调用按工具要求带回。
- 编号、短名、旧名兼容及派生规则只按 [共用方法的会话命名](../../docs/METHOD.md#会话命名)。从案头任期、板上散活登记行号或已派记录确定名称；平台层不另设会话计数器。
- **不得为取号调用 `list_threads`、分页历史或扫描会话元数据。** 列表只用于身份、状态和地址核验；50 条等返回限制不影响取号。标题成功后优先用已知 ID 的 `read_thread` 定点核对标题、ID 与项目，再按共用流程同步案和板；不直接改内部会话存储。
- 身份记录为 `codex + 完整 threadId + 可读名称`。工具缺失或无法可靠确认时写“UI 名称未同步 / ID 未取得”，保留文件协作，不伪造已改名或已接管。

## 聊天与子任务

| 目的 | 当前桌面可用能力 | 使用边界 |
|---|---|---|
| 列出/读取聊天 | `list_threads`, `read_thread` | 按项目与精确 ID 定位，按需读，不遍历整个账户历史 |
| 查询执行进展 | `wait_threads` | 即时状态可用 `timeoutMs: 0`；持续等待用返回游标，避免忙轮询 |
| 创建独立聊天 | `list_projects` → `create_thread` | 用户明确要求新聊天时使用；返回 pending/clientThreadId 不等于已开始，后续须确认正式 ID 与状态 |
| 给已有聊天派活 | `send_message_to_thread` | 需要用户明确授权该目标或包含它的持续协调；接到另一聊天消息不自动授权回信 |
| 当前请求的子任务 | 可用的 subagent 工具 | 受当前多代理指令与用户授权约束；不拿 create_thread 代替内部子任务 |
| 分叉聊天 | `fork_thread` | 继承历史；与仅加载案文件的新会话 takeover 不等价，审核时分开记 |

授权已经明确就继续，不反复索要确认。缺少授权时先把自足任务书和收件材料写完整，再询问唯一必要的派发决定。创建了用户要求的聊天后，记录返回 ID，按当前工具要求展示创建结果并确认执行状态；create 返回成功不代表任务完成。工具不可用时提供接手 prompt；不通过猜内部数据库或控制 UI 冒充工具成功。

需要延后处理的事项按共用方法持久化到 I/独立来件文件。消息工具只是通知，平台运行状态不替代案的事实状态。

## 交接与归档

`ctx-handoff` 的交接分支在保存核验并释放持笔后，必须执行[共用退役标记规则](../../docs/METHOD.md#交接后的会话退役标记)。依据交接记录中的旧会话 ID/原标题，用实际可用的 `set_thread_title` 设置一次 `✕ ` 前缀，并用 `read_thread` 定点核验；已带前缀则不重复调用改名。只有确知当前聊天就是交出目标时才可省略 `threadId`，不得从继任案头取 ID 误改新会话。

工具缺失或失败时记录“UI 标记未完成”及原因，与已完成的文件交接/释放分别报告；结果无法确认时标待核验。重试只处理旧会话标题，不重写已被继任接管的案或板，不改内部会话存储。退役不删除、归档或关闭聊天，不停进程、不 commit/push、不创建继任；用户要在原会话继续时仍可响应，需重新持笔则按正式接手。

用户明确要求归档时用可用的 `set_thread_archived`，先确认没有依赖当前协调的未回收任务。UI 改名/归档与案状态分开报告。

## 长上下文、用量和审核

- 允许 Codex 原生压缩。固定 500k、超过一小时、50% 占用目前都不触发自动交接；详见 [证据](../EVIDENCE.md)。
- 不发无任务意义的保温请求，不用 Claude 的 `cache-audit.py` 分析 Codex 数据，不移植 `input + 0.1×read + 2×write + 5×output` 公式。
- `get_usage_limits` 如可用，仅提供账户额度窗口，不能当本案/本请求的账单。多聊天同时运行时不能把前后额度差全算给一个案。
- 只读已授权范围内、确实可用的用量/日志。若有 `input_tokens`、`cached_input_tokens`、输出、时间、当前上下文窗口等字段，先确认其每请求/累计含义再使用。字段或成本不可见就写未知，不为凑报表读取认证文件或猜计费映射。
- `ctx-checkup` 先做协作一致性审核，再按真实样本检查两个问题。Codex 统计脚本源码在 `codex/setup/scripts/token-audit.py`，打包后在 `ctx-checkup/scripts/token-audit.py`。只接受显式指定的 rollout JSONL 或 context-kit 用量快照，不自动扫描账户；返回逐响应、会话与模型分组的原始 token 和固定权重加权 token 数，不计算金额或订阅额度。
- 优先使用 `token_usage_record.usage` 并按响应 ID 去重；`token_count` 只交叉校验。旧日志可自动回退累计增量，须报告这是兼容估计，不把一个累计增量称为确定的一次模型请求。缺失、冲突、计数重置和累计不一致必须查看 JSON 的 `issues`/`source_files`，不能只看汇总表。
- 默认 `codex-astra-fixed-v1` 仅对精确模型 `gpt-6-astra` 使用非缓存输入 1、缓存读取 0.1、输出 5；其他模型仍输出原始计数，加权值标未知。模型或统计配置变化分组处理；同组 A/B 固定相同权重配置，不从加权值推算价格或额度。

## 案生命周期

结案、终止、合并和恢复只执行[共用生命周期](../../workflows/case-lifecycle.md)，状态判定与收尾规则不在平台层另定义。案已结束不代表平台聊天已归档或进程已停止；需要核验实际载体时使用本平台已知 ID 与可用工具。用户只要求结束案时，不自动退役当前聊天；标题、归档、进程与跨会话消息分别按实际授权和工具结果记录。

## 方案送审

- 使用 `$ctx-review to claude` 或自然语言，按[共用送审流程](../../workflows/review.md)处理。`to` 是目标信息，不是 shell 命令。
- 用户明确送 Claude 审核时，默认按[CLI 调用约定](../../workflows/review-cli.md)直接发起并回收，模型为 Fable 5.1 Extra High。显式设项目 cwd，用可持续监测的进程句柄；轮询返回不等于进程结束，不以固定运行时间强制杀掉正常任务。
- 审核方只接收简短请求和必要原文；版本、身份、日志与次数由 Codex 记录，不让对方逐项复核。用户明确选择人工链路时才准备转读提示；旧入口冲突单独报告，不自动清理或改权限。
- 收到“审核好了”也可从当前案定位并回收已有回执；未要求审核时不后台启动模型。最终结论、拟改范围与影响交用户确认后再修改文件。
