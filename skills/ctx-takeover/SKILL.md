# 接手：只读案 → 署名 → 复述

参数 = 案号（如 `C-07`）或案文件路径。

## 1. 定位
给了路径就用路径；给了案号就在**当前项目根内**的案库（项目根=有 `.git` 取 git 根、否则 cwd；库位优先 `_ops/CASES/`，否则 `cases/`）里 glob `<案号>*.md`——**不去别的项目的案库找**。
- 命中 0 个：列出目录里所有案请用户指认，**不要猜**。
- 命中多个：列出候选请用户选。

## 2. 只读案文件
**禁读任何旧会话转录（jsonl）**，包括 G 节列出的路径——G 是"仅备查"，只有当前问题明确需要取证时才定点取一次。

优先读 头行 + A~E **+ 收件位**（案里的 §I，或本线线件里的同名节）；F/G/H 扫一眼知道有什么即可。
**收件位必读，不许略过**——跨线来话与前任留给继任的待办都在那儿，处置栏空着的就是等你办的。漏读实测发生过一次：前任把 6 条（含 3 条 ★）写进收件位，继任按旧条文只读 A~E，当场全丢。**别为"更全面"去通读交货件**——要用时再定点读。案文件就是设计来够用的；读转录既贵又会把已被否决的死分支拖回来。

## 3. 署名（交接完成的唯一信号）
- 头行状态若是**『收口中(勿接)』**：不署名、不复述，回复"该案正在收口，稍候再接"。仅当其『更新』时间戳过旧（>1 天）或用户确认收口会话已死，才可强接——强接须声明"接的是半收口案"，复述前先对 B~H 查漏一遍。
- 先看头行"持笔"栏：**已有名字且不是本会话 → 先警告**："该案持笔为 X，可能有另一会话正在接手，双接会撕账"，用户确认后再改（状态已是"候接手"且持笔标"前任已退役"的不算双接，直接署名）。
- 标题：现标题若是负责人手设的（非系统自动生成的摘要形）→ **沿用现名**并以它署名；否则 `set_session_title` 设为 **`[<项目前缀>-]NN-任务内容[-线简称]-角色`**（**NN 在本项目内自增**：会话清单是全部项目混排的，先按工作目录筛出本项目的再取最大 +1；**非主项目加项目前缀**，否则侧栏会出现两个同号认不出谁是谁。取不到则省略，撞号=后开者改；线简称只在任务名看不出线时才写，用线文件的短名不用代号；角色=`导师`|`执行`；不写案名,案本身就是任务粒度）。工具不存在或调用失败时跳过，并在回复里说明"UI 标题未同步"，持笔照改。
- 头行"持笔"改成这个名字（能拿到 UUID 就写 `名字 @UUID前8`），"更新"改成今天。
- **线主槽**：本案所属线若有线件，看它的"线主"栏——**空着或标着已退役就顺手签上自己**（跨线投递的第一查查的就是这个槽，挂着死名字等于把路由架空）；**槽里已有别的活会话就不动**，一线一主同一案一笔。

## 4. 四层复述（证明接住了，且目标链在手）
1. **产品总目标与全局计划**：本案服务哪个总目标、挂在全局计划哪个节点——读总览件（任务板头部）；无总览件则用案 A 节 R 栏，并提示补建；
2. **本案目标与整体计划**：A 节目标一句 + B 节路线一句；
3. **当前进展**：**必报读数**（M 指标现值或 E 台账最新判定），有数报数，无数明说；
4. **下一步**最该做的一件事一句。

每层一两句。不复述全案，不在这一步提改进建议。

**收件位若有未处置行**：复述末尾再加一句——待处置 N 条、最要紧的一条是什么。有就必须报，没有就说"收件位无待处置"。

## 5. 候抽查
末尾一句：**等你抽查提问，通过后我继续本案工作。**

被抽查时的作答纪律：
- 答案在案里 → 直接答，注明出自哪一节。
- 案里没有 → **先直说"案里没有"**，再按 G / H 的指针定点取一次，注明来源。
- 取不到 → 说取不到。**不编造、不脑补、不用常识填空**——抽查里有一道负对照就是专门测这个的。

## 6. 接手后的第一批动作
把"边讨论边落盘"接上：每拍一个决策当场写 C 节，每改一版方案当场重写 B 节；派活按派活判据选载体；本会话过 150k 或到批界，主动提议 ctx-handoff。
