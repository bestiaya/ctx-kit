# ctx-kit

English: [README.md](README.md)

**一次会话装不下的活，才需要 ctx-kit；一次会话能出货的活，用不上。**

给谁用：你手里的活是长期、多线、复杂的产品或工具设计，跨天、跨会话、跨电脑，甚至跨模型跨工具；你对上下文有洁癖，不想让会话越养越肥。

一句话：claude CLI 的会话生命周期工具包——把"状态写在文件里、会话随时能扔"变成默认动作。（claude CLI 是那层跑模型、带工具、管会话的软件，也就是 agent runtime；里面跑的模型可以换，你的会话住在这一层。）

## 你是不是遇到过这几件事

### "Claude 订阅用完了，想换别的 agent 接着干，怎么办？"

这句话是我自己问出来的。订阅中途到期，手上一堆活没干完，那天我才发现能带走的只有我的记忆：目标、拍过的板、走过的死路，全锁在一个快要死的会话里，重讲一遍还讲不全。后来我把状态搬进文件，第一次真交接还是栽了一跤：前一个会话留给继任的几条待办写在文件靠后的位置，继任按老规矩只读前几节，一条没看见，当场全丢。所以这套东西的立场很轴——别指望下一个会话（或下一个模型）记得住什么，该记的当场写死在文件里，会话就随时可以扔。

这个问题有两个日常版："我开了新会话，想接着上个会话干"和"新模型发布了，手上几个会话都想换过去"。三句话问的是同一件事——**状态住在一个快要死的会话里**。

换模型这一版最近就轮到我头上：写这段的当天 Fable 5.1 到手。为什么不在原会话里 `/model` 切一下？缓存按模型隔离——我实测过一次，切过去那一刻，原来那个模型建起来的缓存一条也没读回来（01 §3.8）。所以肥会话该开新会话接手，只付一份状态文件的钱；会话还瘦就直接切。一批会话一起换，见 04-HANDBOOK 的配方"换模型日"。

两波试点实测：新会话把活接过去，开题那一轮只花老会话"凉了再回来"那一次的 **7~8%**——接手不是从头再来，成本只是老会话回一次的零头。体积那头：一个攒到 83 万 token 的会话，全部可接手状态压成约 14KB 一份文件——会话里真正值得带走的就这么点。（读数出自 01 §3.4。）

那份文件叫**案文件**：一个问题域的全部可接手状态，一案一个 md 文件。继任只读它、禁读旧会话转录，署名接管后先复述一遍目标与进展，候你抽查——说一句"接手 C-07"，或 `/ctx-takeover C-NN`。

案文件是纯 markdown，没有 Claude 专属字段，继任不一定是 Claude：跨工具接手用 Codex 实走过一次，复述与抽查全过，含一道专测编造的负对照；换一台电脑是设计上如此——交接本就要求 commit 并 push，状态随仓库走；交给同事也是读同一份文件。上面两个数字都来自 Claude 接 Claude。

### "这会话上下文用掉一半了，怎么办"

长会话越养越贵，钱漏在你看不见的地方。

两个长寿讨论会话的账单审计：总花费的 **56~57%** 是把同一段内容反复重写进缓存（01 §3.3）——长会话过半的钱不买新东西，只买"把说过的话再抄一遍"。会话内缓存本来就几乎全命中、没有参数可调，省钱的杠杆不在缓存设置上，在"这个会话什么时候该关"。

先别急着压缩。compact（客户端把长会话压成摘要的内置动作）保的是"还能接着聊"、丢的是细节，一次实测**丢掉 98.8%**（01 §3.6）；且只有压完还接着用才回本，压完就走等于白付一次重建费。你要保的是结论与状态，不是聊天记录。

把讨论沉淀成一份可接手的案文件，把聊过却没落盘的东西落盘，然后这个会话退役——这套动作叫**收口**：说一句"收口"，或 `/ctx-handoff`。它不自作主张：会话过线只报一句当前水位、问你要不要收，你说了才收。

### "我想有个地方管着我所有的活"

多个活并行却没有总账，"现在什么情况"自己都答不上来；聊过的东西散在各个会话里，不知道漏没漏。

项目开工时说一句"新项目开工"（`/ctx-init`），它先读你自己的文档，把"这项目要拿到什么、有哪几件大事"提议成一屏，每格标出处、读不出的写"待你答"，你确认之前一个字都不写。之后你只管说事：新活它自己分诊，该立案的当场建档，一次干得完的板上记一行；临时想起的待办说一句"记一下"，它按归属落进该去的地方，回你一句存到哪、哪一节。想知道现在什么情况，让它读总账与各案用人话报给你（`/ctx-status`）；计划变了再跑一次 `/ctx-init`，它拿现在的板当基线只提差异。

案做完了，收口就是关案：标上已关、决议上交、板上那行挪到表末，不再有人接手。收口还会当场清点"聊过却没写进文件的东西"，两波试点分别清出 **7 项和 14 项**（01 §3.4），后一波还自报了几处账错和不可复现的数字；不清点，这些就随会话消失。

说事、记待办、立案都走这一条：`/ctx-kickoff`。

### "我想派个活给下一个会话去干"

子代理不给主会话续命：它跑它的，账记在它自己头上，你这边的缓存该凉照凉；等它回来那一下，整段上下文按会话当时的水位（已用掉的上下文量）重付一遍。所以高水位会话不派子代理。

该派的活写成任务书落盘，交给新会话去干。`/ctx-kickoff` 只问你一个问题——在这儿聊还是派出去；答"派出去"，它就把这份自足的任务书写好，交给新会话接。

## 你需不需要它：三问自测

三问其实是同一问：**你的活比一次会话大吗？**

1. 这个会话会养肥吗？——聊到你舍不得关，隔天还要回去。
2. 这件活比会话活得久吗？——明天要接着干，可能换会话、换 agent、甚至换台电脑。
3. 同时推进的活多于一件吗？——需要一个地方回答"现在什么情况"。

像这些活，就是"装不下"的活：

- 追了三天的疑难 bug：假设、实验、排除来回循环，案文件就是那本实验记录本，新会话只读它就能接着追。
- 技术调研与选型：查料、横比、验证、拍板，决策连同"为什么"落在一处，半年后不用考古。
- 大型重构或迁移：几百个文件分批改、几个会话并行跑，台账与分波抽验都在文件里，编排会话只派不干。
- 几件事同时推进：项目、客户、side project 各一条线，一块任务板就能回答"现在什么情况"。

三问全"否"——比如一次会话内就能出货的快活，写个 PRD、生成用户故事、出一段代码——**你用不上 ctx-kit，别装**。哪一问是"是"，就开对应那层：①经济纪律 ②案文件 ③任务板；哪类工作装哪几层，见 02-METHOD 第 5 章与 04 的配方。

## 它是什么、凭什么、不是什么

一条铁律：**状态在盘上，会话可抛弃**——结论当场写进文件，会话随时能关掉重开。

它信这五条：

- **会话是耗材，活是主体** — 活要比会话活得久，状态就得住在会话之外的文件里。
- **两个根，一个方向** — 钱说"低水位、连续、用完即弃"最省，连续性说"状态得在盘上"，两条指向同一个动作。
- **纪律先于工具** — 每条做法不装东西也成立，手工照做同样有效；kit 只省掉"想起来要做"和"记得怎么做"。
- **可验证优先于可描述** — 数字要有出处，措辞跟着证据档位走，交接要能考。
- **人只做三个动作** — 说事、问进展、拍板，其余模型自己判；对外先说清什么时候用不上。

概念只有一句：状态住在三样东西里——任务板、案、件；会话随时可扔。

顺带，你得到一套够用的计划与任务管理。开工时它先读你的文档，把"这项目要拿到什么、有哪几件大事"写成一屏，你确认一次。之后每件事都挂在这一屏上：大事下面是案，案里记着试过什么、定了什么、还等你拍什么。想知道进展，问一句，它读板和案用人话回答；计划变了，重跑一次开工；案做完了，收口就是关案。它不排日期、不管人力、不做风险登记，一个案一份 markdown，没有系统。你要做的还是三个动作：说事、问进展、拍板。

它不解决什么：不是缓存调优工具（会话内缓存几乎全命中，没可调空间），也不改你的编码流程；它管的是会话什么时候开、什么时候关、状态住哪。

一条诚实边界：150k 黄灯 / 200k 红灯这两条水位线**是按钱定的，不是按质量定的**。质量那一面只有厂商文档的定性承认——token 越多，准确率与召回越差（context rot，官方未给任何百分比）；本 kit 没做本地测量，不拿它当任何阈值的依据（见 01 栏二）。

## 装什么

装进去的是 6 个 skill、1 段 CLAUDE.md 条文、1 个提醒 hook、1 个查账脚本、1 个 digest 子代理。三步，两条命令加一次粘贴：

```bash
claude plugin marketplace add bestiaya/ctx-kit
claude plugin install ctx-kit@ctx-kit
```

第三步（手动，必做）：把 [CLAUDE-snippet.md](CLAUDE-snippet.md) 里的代码块整段拷进项目 `CLAUDE.md`（或 `~/.claude/CLAUDE.md`）。plugin 装得进 skill、hook、脚本和子代理，**装不进常驻条文**——而"说事先分诊、大料自动下放、过线提醒收口"这些主动行为全靠条文常驻。

<details><summary>手动安装（不走 plugin）</summary>

把 `skills/ctx-*` 拷进 `.claude/skills/`、`agents/digest.md` 拷进 `.claude/agents/`、`hooks/hooks.json` 的 `hooks` 段并进 `.claude/settings.json`（macOS 弹通知，其它平台回落 stderr）；条文照上面粘贴；审计脚本留在原地，`python3 <路径>/cache-audit.py --all`。
</details>

装完自查三条：

1. 新开一个会话说"我要做 X"，看它是否先分诊再动手。
2. 让它读一份 >30k 的材料，看它是否派 digest 子代理而不是自己通读。
3. 把会话养到黄灯线以上，看它过线时是否提醒你收口——不提就是条文没加载。

## 读什么

- **01-BACKGROUND.md** — 实验报告：本文所有数字的唯一出处；栏一=本批实测、栏二=经验规则未实测，严格分开。
- **02-METHOD.md** — 使用原则逐条量化、产物体系、目标链、适用场景与完整名词表。
- **03-PLAYBOOK.md** — 定义一个工具类产品的流程模板：五步、六层金字塔、红线清单。用它定义了 ctx-kit 自己，一次。
- **04-HANDBOOK.md** — 按上面四句原话组织，一句一节直达操作；外加按工作形态的配方、3+1 抽查与故障排查。
- **05-FAQ.md** — 一条一个原话疑问，含"传统开发要不要用""上下文过半就变笨靠不靠谱"。

**卸载**：plugin 在 `/plugin` 里移除，手动装的 `rm -rf .claude/skills/ctx-* .claude/agents/digest.md`；再从 `CLAUDE.md` 与 `.claude/settings.json` 删掉对应段落，不留痕迹。

## 本文用到的词

- **任务板** — 一个项目一份：要拿到什么、在干和干过的大事有哪些，一件一行。
- **线** — 板上的一件大事，底下挂着若干案（"过线"的线是水位，不是这个）。
- **案 / 案文件** — 一件大事底下一个要收敛的问题域，一案一份 md：目标、方案、拍过的决策、等你拍的、实验清单、交接备忘。
- **件** — 案的附件：任务书、原始数据、交货件、草案；一件一文件，只增不改。
- **实验行** — 实验清单上的一行：问什么、跑到哪、判定、对方案的影响。
- **会话** — 你和 claude CLI 的一次对话；临时载体，不是账本。
- **收口** — 把会话里的状态沉淀到盘上、会话随即退役。
- **接手** — 新会话只读案文件把案接过去，署名、复述、候你抽查。
- **派活** — 把确定的活写成自足任务书交出去，回来只看交货件。
- **水位** — 会话已用掉的上下文量（tokens）；"高水位"指已过线的会话。
- **agent runtime** — 跑模型、带工具、管会话的那层软件，claude CLI 是其中一个；模型可换，会话住在这一层。
