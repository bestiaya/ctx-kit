# ctx-kit

English: [README.md](README.md)

**一次会话装不下的活，才需要 ctx-kit；一次会话能出货的活，用不上。**

给谁用：你手里的活是长期、多线、复杂的产品或工具设计，跨天、跨会话、跨电脑，甚至跨模型跨工具；你对上下文有洁癖，不想让会话越养越肥。

一句话：claude CLI 的会话生命周期工具包——把"状态写在文件里、会话随时能扔"变成默认动作。（claude CLI 是那层跑模型、带工具、管会话的软件，也就是 agent runtime；里面跑的模型可以换，你的会话住在这一层。）

## 你是不是遇到过这几件事

### "Claude 订阅用完了，想换别的 agent 接着干，怎么办？"

这句话是我自己问出来的。订阅中途到期，手上一堆活没干完，那天我才发现能带走的只有我的记忆：目标、拍过的板、走过的死路，全锁在一个快要死的会话里，重讲一遍还讲不全。后来我把状态搬进文件，第一次真交接还是栽了一跤：前一个会话留给继任的几条待办写在文件靠后的位置，继任按老规矩只读前几节，一条没看见，当场全丢。所以这套东西的立场很轴——别指望下一个会话（或下一个模型）记得住什么，该记的当场写死在文件里，会话就随时可以扔。

这个问题有两个日常版：一个是"我开了新会话，想接着上个会话干"，一个是"新模型发布了，手上几个会话都想换过去"。三句话问的是同一件事——**状态住在一个快要死的会话里**。

换模型这一版最近就轮到我头上：写这段的当天 Fable 5.1 到手，手上几个会话都想换过去。你可能会问，为什么不在原会话里 `/model` 切一下？官方文档写明缓存按模型隔离；我自己也实测过一次——切过去那一刻，原来那个模型建起来的缓存一条也没读回来，整段上下文按新模型从头写了一遍。所以肥会话切模型，等于把整个上下文重付一遍；开个新会话接手，只付一份状态文件的钱。会话还瘦就直接切，不必换窗口。手上一批会话要一起换，做法见 04-HANDBOOK 的配方"换模型日"。

两波试点实测：新会话把活接过去，开题那一轮只花老会话"凉了再回来"那一次的 **7~8%**——接手不等于从头再来，它的成本只是老会话回一次的零头。体积那一头：一个攒到 83 万 token 的会话，全部可接手状态压成约 14KB 的一份文件——会话里真正值得带走的，就这么点。

那份文件叫**案文件**：一个问题域的全部可接手状态，一案一个 md 文件。继任只读它、禁读旧会话转录，署名接管后先复述一遍目标与进展，候你抽查——`/ctx-takeover C-NN`。

案文件是纯 markdown，没有任何 Claude 专属字段，所以继任不一定是 Claude：跨工具接手用 Codex 实走过一次，复述与抽查全过，含一道专测编造的负对照；换一台电脑是设计上如此——交接动作本就要求 commit 并 push，状态随仓库走；交给同事也是读同一份文件（对方没装 skill，就照手册人工复述加抽查）。上面那两个数字都来自 Claude 接 Claude。

### "这会话上下文用掉一半了，怎么办"

长会话越养越贵，钱漏在你看不见的地方。

两个长寿讨论会话的账单审计结果：总花费的 **56~57%** 是把同一段内容反复重写进缓存——长会话过半的钱不买新东西，只买"把说过的话再抄一遍"。会话内的缓存本来就几乎全命中，没有参数可调，所以省钱的杠杆不在缓存设置上，在"这个会话什么时候该关"。

先别急着压缩。compact（客户端把长会话压成摘要的内置动作）保的是"还能接着聊"、丢的是细节，一次实测**丢掉 98.8%**；而且只有压完还要接着用才回本，压完就走等于白付一次重建费。你真正要保的是结论与状态，不是聊天记录。

把讨论沉淀成一份可接手的案文件，把聊过却没落盘的东西落盘，然后这个会话退役——这套动作叫**收口**，命令是 `/ctx-handoff`。

### "我想有个地方记着我在干的所有活"

多个活并行却没有总账，"现在什么情况"自己都答不上来；聊过的东西散在各个会话里，也不知道漏没漏。

收口时会当场清点一遍"聊过却没写进文件的东西"——两波试点分别清出 **7 项和 14 项**，后一波还自报了几处账错和几个不可复现的数字。不清点，这些就随会话一起消失。

新活先分诊（判断它值不值得单独立一份案文件），当场把档建起来：`/ctx-kickoff`。想知道现在什么情况，让它读总账（任务板）与各份案文件、用人话报给你，不必自己翻文件：`/ctx-status`。

### "我想派个活给下一个会话去干"

子代理不给主会话续命：它跑它的、账记在它自己头上，你这边的缓存该凉照凉。等它回来那一下，整段上下文要按会话当时的水位（已经用掉的上下文量）重付一遍。所以高水位会话不派子代理。

该派的活写成任务书落盘，交给一个新会话去干。`/ctx-kickoff` 只问你一个问题——在这儿聊还是派出去；答"派出去"，它就把这份自足的任务书写好，交给新会话接。

## 你需不需要它：三问自测

三问其实是同一问：**你的活比一次会话大吗？**

1. 这个会话会养肥吗？——聊到你舍不得关，隔天还要回去。
2. 这件活比会话活得久吗？——明天要接着干，可能换会话、换 agent、甚至换台电脑。
3. 同时推进的活多于一件吗？——需要一个地方回答"现在什么情况"。

像这些活，就是"装不下"的活：

- 追了三天的疑难 bug：假设、实验、排除来回循环，案文件就是那本实验记录本，新会话只读它就能接着追。
- 技术调研与选型：查料、横比、验证、拍板，决策连同"为什么"落在一处，半年后不用考古。
- 大型重构或迁移：几百个文件分批改、几个会话并行跑，台账与分波抽验都在文件里，编排会话只派不干。
- 几件事同时推进：项目、客户、side project 各一条线，一块任务板就能回答"现在什么情况"。

三问全"否"——比如一次会话内就能出货的快活，写个 PRD、生成用户故事、出一段代码——**你用不上 ctx-kit，别装**。哪一问是"是"，就开对应那层：①经济纪律 ②案文件 ③任务板；哪类工作装哪几层，见 02-METHOD 第 5 章与 04 的配方。

## 它是什么、不是什么

一条铁律：**状态在盘上，会话可抛弃**——结论当场写进文件，会话随时能关掉重开。原则先于工具存在，手工照做同样有效；kit 只省掉"想起来要做"和"记得怎么做"这两步。

ctx-kit 想留下的不是五个 skill，是一套**轻项目管理**：一案一文件，目标、决策、实验、未决、交接都在那一份文件里。skill 哪天没了，案文件和流程照样用；方法文档才是正文，插件只是让它变成默认动作。说清它有多轻：它只管目标、决策、实验、交接、花费这五件，不管排期、人力、风险登记，轻到只有一份 markdown，没有任何系统。

它不解决什么：不是缓存调优工具（会话内缓存本来就几乎全命中，没有可调空间），也不改你的编码流程；它管的是会话什么时候开、什么时候关、状态住在哪。

一条诚实边界：150k 黄灯 / 200k 红灯这两条水位线**是按钱定的，不是按质量定的**。质量那一面只有厂商文档的定性承认——token 越多，准确率与召回越差（context rot，官方未给任何百分比）；本 kit 没做本地测量，不拿它当任何阈值的依据。

## 装什么

装进去的是 5 个 skill、1 段 CLAUDE.md 条文、1 个提醒 hook、1 个查账脚本、1 个 digest 子代理。三步——两条命令加一次粘贴：

```bash
claude plugin marketplace add demontunes/ctx-kit
claude plugin install ctx-kit@ctx-kit
```

第三步（手动，必做）：把 [CLAUDE-snippet.md](CLAUDE-snippet.md) 里代码块的内容整段拷进项目 `CLAUDE.md`（或 `~/.claude/CLAUDE.md`）。plugin 装得进 skill、hook、审计脚本和 digest 子代理，**装不进常驻条文**——而"说事先分诊、大料自动下放、过黄灯线主动提收口"这些主动行为全靠条文常驻。

<details>
<summary>手动安装（不走 plugin）</summary>

```bash
KIT=path/to/ctx-kit
mkdir -p .claude/skills .claude/agents
cp -R "$KIT"/skills/ctx-* .claude/skills/
cp    "$KIT"/agents/digest.md .claude/agents/
```

再把 `hooks/hooks.json` 的 `hooks` 段并进 `.claude/settings.json`（macOS 弹通知，其它平台回落 stderr）；条文照上面粘贴；审计脚本留在原地，`python3 <路径>/cache-audit.py --all`。

</details>

装完自查三条：

1. 新开一个会话说"我要做 X"，看它是否先分诊再动手。
2. 让它读一份 >30k 的材料，看它是否派 digest 子代理而不是自己通读。
3. 把会话养到黄灯线以上，看它是否主动提收口——不提就是条文没加载。

## 五个 skill

| skill | 什么时候触发 | 干什么 |
|---|---|---|
| **ctx-kickoff** | 你说"我要做 X""开个新活"，或 `/ctx-kickoff` | 分诊（该立案 / 不必立案 / 顺手改就完）→ 当场建案文件 → 只问一个问题：在这儿聊还是派出去 |
| **ctx-handoff** | 你说"收口""这会话上下文太满了"，或 `/ctx-handoff` | 讨论沉淀成可接手的案文件（含未落盘清单）→ 未落盘产物落盘 → 本会话退役 |
| **ctx-takeover** | 你说"接手 C-07""继续那个案"，或 `/ctx-takeover C-NN` | 只读案文件（禁读旧会话转录）→ 署名接管 → 四层复述 → 候你抽查 |
| **ctx-status** | 你说"现在什么情况""进展如何""看一下板"，或 `/ctx-status` | 读任务板与案文件，人话汇报目标链、各案状态、待拍板项与零散的活，不让你翻文件 |
| **ctx-checkup** | 你说"周检""查查会话花费"，或 `/ctx-checkup` | 跑缓存审计 → 按预注册判据判读越线会话 → 回填案文件的档案指针 |

案文件放哪：优先用已存在的 `_ops/CASES/`，否则用 `cases/`（没有就创建）。

## 读什么

- **README.md** — 英文主入口，给国际访客与收录渠道。
- **01-BACKGROUND.md** — 实验报告：测什么、怎么测、五组对照读数，本文所有数字的唯一出处；栏一=本批实测、栏二=经验规则未实测，两栏严格分开。
- **02-METHOD.md** — 使用原则逐条量化、产物体系、目标链、原则→skill 对照表、适用场景与完整名词表。
- **03-PLAYBOOK.md** — 定义一个工具类产品的流程模板：五步、六层金字塔、红线清单。用它定义了 ctx-kit 自己，一次。
- **04-HANDBOOK.md** — 按上面四句原话组织，一句一节直达操作；外加按工作形态的配方（含最小用法与跨会话通讯纪律）、3+1 抽查菜谱与故障排查。
- **05-FAQ.md** — 一条一个原话疑问，含"传统开发要不要用""为什么不按会话建档""上下文过半就变笨靠不靠谱"。

赶时间：先看 04 里对得上你处境的那一节，装完再回头翻 02。

**卸载**：plugin 装的在 `/plugin` 里移除，再从 `CLAUDE.md` 删掉条文段；手动装的 `rm -rf .claude/skills/ctx-* .claude/agents/digest.md`，并清掉 `CLAUDE.md` 与 `.claude/settings.json` 里的对应段落——kit 不留任何其他痕迹。

## 本文用到的词

- **案文件** — 一个问题域的全部可接手状态，一案一个 md 文件（目标 / 方案 / 决策 / 实验 / 未决）。
- **收口** — 把会话里的状态沉淀到盘上、会话随即退役的动作。
- **水位** — 会话已经用掉的上下文量（tokens）。"高水位"指用量已过线的会话。
- **agent runtime** — 跑模型、带工具、管会话的那层软件，claude CLI 就是其中一个。模型可以换，会话住在这一层。

完整名词表见 02-METHOD.md。
