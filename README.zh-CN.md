# ctx-kit

English: [README.md](README.md) · 六条命令的 skill 正本是英文，每个旁边的 `SKILL.zh-CN.md` 是中文参考件——它是快照、会滞后于英文正本，头一行写着冻结在哪一版。

**一次会话装不下的活，才需要 ctx-kit；一次会话能出货的活，用不上。**

## TL;DR

**一句话**：claude CLI 的会话生命周期工具包——把"状态写在文件里、会话随时能扔"变成默认动作，让活比会话活得久。（claude CLI 就是你用的那个 agent：跑模型、带工具、管会话；模型可以换，你的会话住在它这一层。）

**适用**：给 claude CLI（Claude Code）做的——六条命令是它的 skill，钩子与审计脚本读的是它的会话日志。案文件是纯 markdown，别的 agent 也能读：换 Codex 接手实走过一次；但给 Codex 用的命令那一层还没做，要另做一版。

**给谁用**：拿 agent 干"比一次会话大"的活的人——写代码、做产品设计、做调研、写东西都算。这种活的会话会越养越贵，活要跨会话、跨 agent、跨电脑，手上还不止一件事。一次会话内就能出货的快活（写个 PRD、生成用户故事、出一段代码），用不上。

**解决三个问题**：

1. 长会话上下文过载：钱烧在把说过的话反复重写进缓存，放凉再回来整段重付一遍，自动压缩还丢细节。
2. 换会话、换模型、换电脑、被自动压缩之后信息断档，又得从头讲一遍。
3. 多任务并行的记录、跟踪、恢复执行，以及任务之间的通讯（用的是 claude CLI 自带的跨会话消息：v2.1.224 起有 SendMessage / ListAgents，2026-08-07 加入；v2.1.236 起有空闲订阅 notify_when_idle，2026-08-19 加入）——没有黑科技，全是 agent 自带的能力（几个会话怎么排、话怎么传，见 06 的[配方 5](06-RECIPES.md#配方-5多会话并行--跨会话通讯)与[样例 B](06-RECIPES.md#样例-ba-会话定标准b-会话执行a-有新想法怎么告诉-b)）。

**数据**（四条实测，点开是出处与样本）：

- 新会话把活接过去，开题那一轮只花老会话"凉了再回来"一次的 **7~8%**（[01 §3.4](01-BACKGROUND.md#34-对照-2继续养着老会话--收口换生)）
- 长会话总花费的 **56~57%**，买的是"把说过的话再抄一遍"（[01 §3.3](01-BACKGROUND.md#33-对照-5调缓存参数--改生命周期纪律)）
- 自动压缩一次，丢掉 **98.8%** 的细节（[01 §3.6](01-BACKGROUND.md#36-auto-compact-实录与-compact-的账面盲区)）
- 一个攒到 83 万 token 的会话，全部可接手状态压成 **约 14KB 一份文件**（[01 §3.4](01-BACKGROUND.md#34-对照-2继续养着老会话--收口换生)）

## 你是不是遇到过这几件事

### "又得从头给它讲一遍"

**解决什么**：撞了额度上限、活干到一半它死了、上下文满了被自动压缩、换电脑换模型换 agent——这些事之后活能接着干，不用把前情重讲一遍。

**用户心声**（三路公开讨论取样，只取用户自己的说法）：

> - 又忘了，昨天刚跟它说过的事（"forgets everything between sessions"）
> - 像在带一个失忆的实习生（"babysitting an intern with amnesia"）
> - 干到一半它死了，撞上限被切断，活断在半路（"died mid-task"、"hit the limit"）
> - 每开一个新会话都从零讲起，上次干到哪只能自己留张条（"every session starts cold"、"where I left off"）
> - 换台电脑就接不上，记忆写死在本机目录；会话记录本身也会过期

**数据**：新会话把活接过去，开题那一轮只花老会话冷回访一次的 7~8%；一个攒到 83 万 token 的会话，全部可接手状态压成约 14KB 一份文件（两个读数出自 01 §3.4，都是 Claude 接 Claude）。

**怎么做**：

1. 干活当中，它把结论当场写进一份**案文件**——一个 md 文件，装着这件活的全部状态：目标、定过的事、试过的死路、下一步。
2. 这个会话该扔了，跟它说"收口"（`/ctx-handoff`）：没写下来的东西当场补进文件，会话随即退役。
3. 开个新会话说"接手 C-07"（`/ctx-takeover C-NN`）：它只读那份文件、不许翻旧会话记录，先把目标与进展复述一遍候你抽查。
4. 换电脑、换 agent 也走这一步——文件是纯 markdown，换成 Codex 接手实走过一次；想换模型别在原会话里切，实测过一次，切过去旧缓存一条也没读回来（01 §3.8）。
5. 这活想交出去干，先说给它听（`/ctx-kickoff`）：它只问你一句——在这儿聊，还是写成任务书派给新会话。

### "长会话越养越贵"

**解决什么**：三笔冤枉钱——会话放凉再回来，整段上下文重付一遍；一直养着的长会话，钱大半买的是"把说过的话再抄一遍"；自动压缩顶上来，细节又被压没。这三笔靠"及时收口、开新会话接手"这一个动作省掉；账单看得见是顺带的。

**用户心声**（同一批取样）：

> - 长会话越养越贵，钱不买新东西，只买"把说过的话再抄一遍"
> - 会话放凉再回来，整段上下文重新计费（"the prompt cache has expired"）
> - 自动压缩最烦人，摘要一压，细节全没了（"auto compact is the worst"、"the summary is lossy"）
> - 撞了限额，却查不出 token 到底花在哪（"Real cost, no visibility"）
> - 时间都花在伺候 AI 上，不在干活上（"spending more time managing the AI"）

**数据**：会话放凉一个多小时再回来，整段上下文重付一次，这一次的税 = 你当时的水位 × 2（01 §3.2）；两个长寿会话的账单审计，总花费的 56~57% 是把同一段内容反复重写进缓存（01 §3.3）；压缩保的是"还能接着聊"、丢的是细节，一次实测丢掉 98.8%（01 §3.6）。换成收口再接手，新会话开题那一轮只花冷回访一次的 7~8%（01 §3.4）——这就是那三笔钱省下来的样子。

**怎么做**：

1. 会话变贵时它主动问一句要不要收口——你说一句"收口"（`/ctx-handoff`）它才收，然后开个新会话说"接手"接着干。**省钱的主动作就是这一下**，越早做省得越多。
2. 别拿压缩顶着：压缩保的是"还能接着聊"，你要保的是结论与状态；该关就关，别拿压缩给会话续命。
3. 会话已经很贵的时候别派子代理出去——它回来那一下，整段上下文按当时的量重付一次。
4. 一周查一次账，说"周检"（`/ctx-checkup`）：这周 token 花在哪、哪个会话该关了，它列给你看，确认钱花在该花的地方。

### "几个会话并行，哪个在等我、干到哪了？"

**解决什么**：几件活同时推进时，有一个地方能回答"现在什么情况"——哪件在等你定夺、哪件干完了、哪些聊过却没落地。

**用户心声**（同一批取样）：

> - 两条会话并行，不手动去看就不知道另一条刚改了什么（"no idea what the other session just changed"）
> - 一条在重构辅助函数、另一条在给它写测试，合到一起一团糟
> - 几个会话同时开着，哪个在等人定夺、哪个已经干完，只能挨个切标签页看（"tired of cmd-tabbing between terminal tabs"）
> - 项目一大就跟丢下一步，也说不清到底完成了多少（"not knowing how much is actually finished"）
> - 聊过的东西散在各个会话里，待办说过就丢

**数据**：一波试点在收口时清点出一串"聊过却没写进文件"的东西（01 §3.4），连几处账错也一并自报了；不清点，这些就随会话消失。

**怎么做**：

1. 项目开工说一句"新项目开工"（`/ctx-init`）：它先读你自己的文档，把"这项目要拿到什么、有哪几条里程碑、有哪几件例行一直在跑"提议成一屏、每格标出处，你点头之前一个字都不写。
2. 之后你只管说事（`/ctx-kickoff`）：它自己分诊——要跟进的当场建档，一次干得完的记一行。
3. 待办随口一句"记一下"，它按归属落盘，回你一句存到哪了。
4. 想知道现在什么情况，问它一句（`/ctx-status`）：它把所有记录读一遍，用人话报给你。
5. 一件活做完，说"收口"就是关案：标上已关，顺手清点聊过却没写下来的东西。

这三件事不是拍脑袋编的，是从 X、GitHub、Reddit 上用户自己的抱怨里归出来的；怎么归的、样本多大，见下面"凭什么信"最后一行。

## 你需不需要它：三问自测

三问其实是同一问：**你的活比一次会话大吗？**

1. 这个会话会越养越贵吗？——聊到你舍不得关，隔天还要回去。
2. 这件活比会话活得久吗？——明天要接着干，可能换会话、换 agent、甚至换台电脑。
3. 同时推进的活多于一件吗？——需要一个地方回答"现在什么情况"。

像这些活，就是"装不下"的活：

- 追了三天的疑难 bug：假设、实验、排除来回循环，案文件就是那本实验记录本，新会话只读它就能接着追。
- 技术调研与选型：决策连同"为什么"落在一处，半年后不用考古。
- 大型重构或迁移：几百个文件分批改、几个会话并行跑，台账与分波抽验都在文件里。
- 几件事同时推进：项目、客户、side project 一起在跑，一块任务板就能回答"现在什么情况"。

三问全"否"——比如一次会话内就能出货的快活——**你用不上 ctx-kit，别装**。哪一问是"是"，就开对应那层：①经济纪律 ②案文件 ③任务板；哪类工作装哪几层，见 02-METHOD 第 5 章。

三种常见的反对，我一并答了。①"复制粘贴让它总结一下不就行了"——摘要交接和案文件谁更好，我没做过对照实验，不宣称谁赢（这条边界写在 05-FAQ Q22）。②"交接文件靠自律，几小时后你自己就懒了"——说得对，所以收口做成一条命令、抽查做成必做步骤，纪律写在 skill 里，不靠你记性。③"没碰到过这些问题"——那多半是真的，你的活还没大到装不下，全否就别装。

## 它是什么、凭什么、不是什么

一条铁律：**状态在盘上，会话可抛弃**——结论当场写进文件，会话随时能关掉重开。这条不是推演出来的，是订阅中途到期、一堆活锁在一个快死的会话里那天撞出来的（经过见 05-FAQ Q23）。

它信这五条：

- **会话是耗材，活是主体** — 活要比会话活得久，状态就得住在会话之外的文件里。
- **两个根，一个方向** — 钱说"低水位、连续、用完即弃"最省，连续性说"状态得在盘上"，两条指向同一个动作。
- **纪律先于工具** — 每条做法不装东西也成立，手工照做同样有效；kit 只省掉"想起来要做"和"记得怎么做"。
- **可验证优先于可描述** — 数字要有出处，措辞跟着证据档位走，交接要能考。
- **人只做三个动作** — 说事、问进展、拍板，其余模型自己判；对外先说清什么时候用不上。

概念只有一句：状态住在三样东西里——任务板、案、件；会话随时可扔（逐个解释见文末词表）。

任务板一个项目一份，**手写维护**：板头是总目标 + 一张**里程碑**表（一行一句"拿下后什么为真"+ 状态）+ 一张**例行**表（节奏 + 健康读数 + 上次 / 下一次），下面是案索引与不值立案的散活，各占一行。里程碑是标签，不是案的上级：案与散活各标一条或多条；一条都对不上的活，就写一句"候补里程碑"候你定——是给板上补一条，还是停掉这个活。`/ctx-init` 提议板头、你点头后落，之后各案改各行；想拿脚本生成是可选项，什么都不装也照样成立。

顺带，你得到一套够用的计划与任务管理（就是上面第三个场景那套动作）：它不排日期、不管人力、不做风险登记，一个案一份 markdown，没有系统。

它不解决什么：不是缓存调优工具（会话内缓存几乎全命中，没可调空间），也不改你的编码流程；它管的是会话什么时候开、什么时候关、状态住哪。也不是跨 agent 通用工具：命令与钩子只在 claude CLI 里有，换别的 agent 只能带走文件（Codex 接手实走过一次），命令那层要按那个 agent 另做。

一条诚实边界：黄灯 / 红灯那两条水位线**是按钱定的，不是按质量定的**。质量那一面只有厂商文档的定性承认——token 越多，准确率与召回越差（context rot，官方未给任何百分比）；本 kit 没做本地测量，不拿它当任何阈值的依据（见 01 栏二）。

## 装什么

装进去的是 6 个 skill、1 段 CLAUDE.md 条文、1 个提醒 hook、1 个查账脚本、1 个 digest 子代理。

**先看版本**：`claude --version`。哪一层要什么版本（版本出自 [claude CLI 更新日志](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)）：

| 这一层 | 最低版本 | 版本不够会怎样 |
|---|---|---|
| skill 机制（六条命令的底座） | v2.0.20（"Added support for Claude Skills"） | 整套都不生效，先 `claude update` |
| 按插件装（`claude plugin …`） | v2.0.12 插件机制上线——更新日志没写 `claude plugin` 这个命令行形式是哪一版加的 | 改用会话里的 `/plugin`，或按下面手动安装 |
| 跨会话消息 `SendMessage` / `ListAgents` | v2.1.224（macOS / Linux）；原生 Windows 要 v2.1.239 | 只影响"多会话并行"那一套（06 配方 5），其余照跑 |
| 空闲通知 `notify_when_idle` | v2.1.236（macOS / Linux） | 得你自己去问"跑完没"，没人叫你 |
| UI 会话标题 | 没有版本门槛：桌面版才有设标题的工具，纯终端没有 | 它跳过设标题并说明一句；案里的"持笔"才是唯一的交接信号 |

三步，两条命令加一次粘贴：

```bash
claude plugin marketplace add bestiaya/ctx-kit
claude plugin install ctx-kit@ctx-kit
```

第三步（手动，必做）：把 [CLAUDE-snippet.md](CLAUDE-snippet.md) 里的代码块整段拷进项目 `CLAUDE.md`（或 `~/.claude/CLAUDE.md`）。plugin 装得进 skill、hook、脚本和子代理，**装不进常驻条文**——而"说事先分诊、大料自动下放、过线提醒收口"这些主动行为全靠条文常驻。

**装之前先知道一个副作用**：收口（`/ctx-handoff`）不只是写文件——它会把这轮动过的路径 `git add` 上、提交，并**推送**。在受保护分支或多人共用分支上干活，先想好你要它推到哪里。推不上去（没远端、没权限、有冲突、压根不是 git 项目），它会在回复里明写"未推送 + 原因"，不会闷着。案库要是落在被 git 忽略的目录里（本仓自己就是这样），案文件只落盘、不入库：收口照样明写这一句，这是合法姿势、不算失败；那个目录想跨电脑接手，得你自己同步过去。

装完自查三条：

1. 新开一个会话说"我要做 X"，看它是否先分诊再动手。
2. 让它读一份 >30k 字符（`LC_ALL=en_US.UTF-8 wc -m`）的材料，看它是否派 digest 子代理而不是自己通读。
3. 把会话养到黄灯线以上，看它过线时是否提醒你收口——不提就是条文没加载。

**从旧版升上来**：这一版把板的第二节从"全局计划"换成了**里程碑**表 + **例行**表。老板面不用重建：重跑一次 `/ctx-init` 走复核模式，它提议改名、你原来的行照留。手工那几步（旧"线"那层的行往哪去、案索引怎么补第七列）见 06 的[配方 7](06-RECIPES.md#配方-7老板面迁到新板里程碑--例行)。

**卸载**：plugin 在 `/plugin` 里移除，手动装的 `rm -rf .claude/skills/ctx-* .claude/agents/digest.md ~/.claude/scripts/cache-audit.py`；再从 `CLAUDE.md` 与 `.claude/settings.json` 删掉对应段落——装到你机器上的件就这些，删干净了。留下来的是你自己的东西：`/ctx-init` 建的任务板与案库、`/ctx-handoff` 提交并推上去的历史，这两样不会替你删，留着还是清掉你自己定。

## 六条命令

六个 skill 六条命令，说大白话和打命令是一回事：

| 什么时候 | 说一句 |
|---|---|
| 项目开工 | "新项目开工"，或 `/ctx-init` |
| 有新事要做，或记个待办 | "我要做 X" / "记一下"，或 `/ctx-kickoff` |
| 这会话太贵，或一批活干完 | "收口"，或 `/ctx-handoff` |
| 新会话接着上个会话干 | "接手 C-07"，或 `/ctx-takeover C-NN` |
| 想知道现在什么情况 | "现在什么情况"，或 `/ctx-status` |
| 一周查一次账 | "周检"，或 `/ctx-checkup` |

六条里只有"收口"会动你的仓库：它把这轮动过的文件提交并推送，推不上去会在回复里明写"未推送 + 原因"。

案文件放哪：优先已存在的 `_ops/CASES/`，否则 `cases/`；想放别处就在项目 `CLAUDE.md` 里写一行 `ctx-kit case library: docs/cases`，六个 skill 都照这行找。

## 本文用到的词

- **任务板** — 一个项目一份，手写维护：总目标 + 里程碑表 + 例行表 + 案索引 + 散活，一件一行。
- **里程碑**（milestone） — 板头里程碑表的一行：一句"拿下后什么为真"+ 状态。它是案与散活各自贴的标签，不是它们的上级；一条都对不上的活写"候补里程碑"，候你定是补一条还是停活。
- **例行**（routine） — 板头例行表的一行：按节奏一直做的事 + 健康读数 + 上次 / 下一次。没有终点、不记账；跑例行撞上要收敛的问题，才为那个问题立案。
- **案 / 案文件** — 一个要收敛的问题域，一案一份 md：目标、方案、拍过的决策、等你拍的、实验清单、交接备忘。
- **散活** — 不值立案的一次性活：板上一行 + 一个交货件；跟案一样要标里程碑。
- **件** — 案与散活的附件：任务书、原始数据、交货件、草案；一件一文件，只增不改。
- **实验行** — 实验清单上的一行：问什么、跑到哪、判定、对方案的影响。
- **会话** — 你和 claude CLI 的一次对话；临时载体，不是账本。
- **收口** — 把会话里的状态沉淀到盘上、会话随即退役。
- **接手** — 新会话只读案文件把案接过去，署名、复述、候你抽查。
- **派活** — 把确定的活写成自足任务书交出去，回来只看交货件。
- **压缩（compact）** — 客户端把长会话压成一段摘要的内置动作：保住"还能接着聊"，丢掉细节。
- **子代理** — 主会话派出去干一件小活的临时会话，跑完只把结果交回来。
- **水位** — 会话已用掉的上下文量（tokens）；"高水位"指已过线的会话。
- **agent** — 跑模型、带工具、管会话的那层软件，claude CLI（Claude Code）是其中一个；模型可换，你的会话住在这一层。
