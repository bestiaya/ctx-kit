# Claude CLI 调用约定

仅给调用方读。审核正文用[简短请求](../templates/REVIEW-REQUEST.md)，不要把本页、预算、日志字段或整套技能转给审核方。

## 启动

- 默认审核模型固定为 `claude-fable-5-1`，Extra High 用 `--effort xhigh`。显式用户要求优先；模型不可用或实际返回不符时报告，不静默降级。调用前按需核对本机版本与既有登录来源，不显示凭据，不自动改登录或支付设置。
- 明确设置被审项目的 cwd；轮次材料用绝对路径。cwd 不是权限隔离边界，独立 worktree 也不自动包含未提交材料。
- 默认由调用方把请求和必要原文组装成输入，关闭审核方文件、命令、MCP 和插件工具，结果通过标准输出返回。用户明确需要调查或补读时，按任务授权单独确定必要工具；不能为消除审批直接全量放行。
- 以下是已验证过的本地调用方式。示例文件名须替换为本轮的绝对路径；通过可持续取得进程状态的执行工具启动，保存 PID/执行句柄，不使用固定运行超时或历史试跑脚本的硬终止逻辑。

```bash
claude --safe-mode --tools "" --permission-mode dontAsk \
  --strict-mcp-config --mcp-config '{"mcpServers":{}}' \
  --disable-slash-commands --model claude-fable-5-1 --effort xhigh \
  --output-format stream-json --verbose -p \
  < input.txt > stdout.jsonl 2> stderr.log
```

每轮新 session，通过输入明确携带需要的前轮意见与变更，不用 `--continue` 猜最近会话。正常订阅认证不使用 `--bare`；它不读取订阅登录。记录实际模型与调用参数，不把请求的 effort 当作独立服务端回显。输入哈希只证明提交材料版本，不能声称覆盖 CLI 的系统、环境或仓库上下文。

## 等待与计数

同一目标最多 3 轮内容往返、全任务最多 1 次技术重试，因此最多 4 次 CLI 启动。原案 E 或独立运行记录保存目标、轮次、尝试、状态和证据路径；不建立第二套任务板。准备好不算已发起，进程和会话记录证明启动，有效回执才证明交付完成。

有有效输出、思考活动或工具执行进展时继续等待；只看到进程活着或重复输出不足以证明有进展。定期检查 stdout/stderr 和子进程状态并向用户报告，等待工具一次返回不代表 CLI 失败。长期没有新进展时排查并说明已有结果和等待原因，不自动杀进程重跑。用户明确停止或另定执行时限时按指令处理。

明确失败后先保存部分输出，确认旧进程已经结束。仅暂时网络、进程或输出解析故障适合使用唯一技术重试，输入保持一致；需要补材料、登录或授权的阻塞不靠重试解决。补材料或改变问题后再次请求，属于下一轮内容往返。不得让新尝试与旧进程竞争写回执。

## 接收

调用方保存原始事件、stderr、退出码、时间、session ID、实际模型、工具与权限拒绝信息，并将完整正文原样另存回执。接收时核对输入版本、请求对应关系、result 事件和完整性；权限拒绝若影响必需证据，要报告缺口。缺少字段标未知，不让审核方再调用工具为这些记录补数。

模型不符、内容截断或结果受阻，不能记为评审通过。仅缺结束标记但正文完整时，由调用方核读并标注协议偏差，不修改原回执。有效回执（含指出材料不足的完整回执）计内容往返；技术无效尝试只计启动数与重试额度。按[回收流程](review.md#回收与交付)独立综合后交用户确认。
