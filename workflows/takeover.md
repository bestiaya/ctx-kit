# 接手并继续

先读 [共用方法](../docs/METHOD.md) 中的[会话命名](../docs/METHOD.md#会话命名)、[持笔与并发](../docs/METHOD.md#4-持笔与并发)、[交接状态](../docs/METHOD.md#交接状态)三节与平台身份/工具规则；其余节做到相关步骤时再查，不整读。

1. 用户给绝对路径时核对所属项目；只给案 ID 时在确定的案库查找。无命中或多命中不猜，只问必要的定位问题。
   **认领前检查终态。** 按 [案生命周期](../docs/METHOD.md#案生命周期) 识别已结案/旧 closed。查询历史不认领、不增任期；明确恢复时先走 [恢复流程](case-lifecycle.md#恢复)，再从本流程第 2 步核验、第 4/5 步认领。仅要求接手却未表明恢复意图时说明已结束并确认是否恢复。结案中的案只处理已授权收尾，不套用候接手规则；异常不自动重开。
2. 先量案头字符数（Unicode 字符）并报告是否超 15,000 整理线，再读案头全文：头部、A、B（含继任阅读表与有效约束）、D、E 在跑行、H、I 待处理行。决策、实验、过程三份记录不整读，按 B 下一步定点查。旧的单文件案照常读 A–E、H、I，F/G 只看指针；超线只报告，拆分由持笔在接手后按共用方法做。比对 `inbox/<案ID>/` 文件名中的消息 ID 与案头 I 及过程记录，只打开未登记、未完成或内容有变的来件。比对与定位用固定命令，不让输出带出整行正文：来件 ID 与状态只取两列，`awk -F'|' '/^\| [A-Z][A-Za-z0-9-]+-[0-9]+ \|/{print $2 "|" $6}' <案头> <过程记录>` 对照 `ls inbox/<案ID>/ | cut -d_ -f1`；任务板只取本案行 `grep '^| <案ID> |' TASKBOARD.md`；在记录文件里找内容先 `grep -n` 取行号，再 `sed -n '起,止p'` 读范围。H 的未完成项和待处理来件都是接手内容，不能只读当前方案。
3. 按 B 下一步核对直接相关的原文范围、版本、Git 工作区和正在运行的执行任务，其余做到再查，记录核验边界。核对与对账可派只读子代理，回定位、结论、矛盾与未知（1,000–3,000 字符），不把原文带回。从接手到预先声明的第一个实际动作，方法规则、案头、必读原文与子代理回传合计 30,000 字符以内；预计或实际超过 40,000 时停止无目的扩读，在过程记录写明例外与原因，不为凑预算猜测。不要整读旧会话；缺证时再按已知 ID/路径定点取证。
4. 收口中或已有其他持笔：先确认释放/转交或终止证据，不凭空闲、老时间戳自动抢占。候接手且无现任持笔可直接认领；案头仍由当前身份持笔时重复调用幂等，不新建案、不重置任务状态。已释放后的重新认领按正式接手处理。
5. 写入前再次读头部，发现已改变则停止竞争写入。正式继任读取案头 `任期` / `stint` 并加 1；旧案无字段则本次从 `01` 起算，并说明此前历史见编年。当前持笔同一会话重试不递增；当前持笔的旧案缺字段只报告缺口，已有字段无效或冲突先核实，不猜数。将任期与本平台、当前完整 ID、已核实的名称、时间一起记录，设持笔中；拿不到 ID 标明限制。案号、任务 ID 与历史决策保持不变；工具重试前重读自己的身份/任期，避免重复加号。
6. 持笔只把第 2 步识别的新来件合并到 I，并复查期间新增；已完成记录不重新处理。原始来件保留；标已接收，处理完成后才写完成与证据，完成行移入过程记录。超出授权的请求列入 D。
7. 按 [共用会话命名](../docs/METHOD.md#会话命名) 使用步骤 5 已记录的案号与任期，不再次递增；禁止从会话列表取号。案短名从板读取，旧板缺失时由持笔补齐并告知用户。用户指定名、已派名及运行中的旧名保留。标题成功后同步案头、板上本案持笔镜像及当前载体；工具失败报告 UI 未同步，保留真实名称，不填拟定名冒充已设名。简短复述总目标、本案目标、进展/缺口和下一步。有数报数，案里没有就直说。用户要求继续且不缺必要输入时推进；仅用户要求抽查或真正阻塞才等。第一个实际动作完成后在过程记录的接手读量表记一行：案头字符数、计划读量、实际读量（在单元格内分项写明方法规则、案头、必读原文、定位核对输出、子代理回传；平台 token 读数可选并注明采样时点）与补读。

后续仍按决策当场入 C、方案变化入 B、结果验收入 E 的节奏维护。
