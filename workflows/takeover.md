# 接手并继续

先读 [共用方法](../docs/METHOD.md) 与平台身份/工具规则。

1. 用户给绝对路径时核对所属项目；只给案 ID 时在确定的案库查找。无命中或多命中不猜，只问必要的定位问题。
   **认领前检查终态。** 按 [案生命周期](../docs/METHOD.md#案生命周期) 识别已结案/旧 closed。查询历史不认领、不增任期；明确恢复时先走 [恢复流程](case-lifecycle.md#恢复)，再从本流程第 2 步核验、第 4/5 步认领。仅要求接手却未表明恢复意图时说明已结束并确认是否恢复。结案中的案只处理已授权收尾，不套用候接手规则；异常不自动重开。
2. 读取头部、A–E、H、I，扫描 F/G 指针和 `inbox/<案ID>/`。H 的未完成项和待处理来件都是接手内容，不能只读当前方案。
3. 核对关键文件、Git 工作区和正在运行的执行任务，记录核验边界。不要整读旧会话；缺证时再按已知 ID/路径定点取证。
4. 收口中或已有其他持笔：先确认释放/转交或终止证据，不凭空闲、老时间戳自动抢占。候接手且无现任持笔可直接认领；案头仍由当前身份持笔时重复调用幂等，不新建案、不重置任务状态。已释放后的重新认领按正式接手处理。
5. 写入前再次读头部，发现已改变则停止竞争写入。正式继任读取案头 `任期` / `stint` 并加 1；旧案无字段则本次从 `01` 起算，并说明此前历史见编年。当前持笔同一会话重试不递增；当前持笔的旧案缺字段只报告缺口，已有字段无效或冲突先核实，不猜数。将任期与本平台、当前完整 ID、已核实的名称、时间一起记录，设持笔中；拿不到 ID 标明限制。案号、任务 ID 与历史决策保持不变；工具重试前重读自己的身份/任期，避免重复加号。
6. 持笔合并 inbox 到 I，用 ID 去重。原始来件保留；标已接收，处理完成后才写完成与证据。超出授权的请求列入 D。
7. 按 [共用会话命名](../docs/METHOD.md#会话命名) 使用步骤 5 已记录的案号与任期，不再次递增；禁止从会话列表取号。案短名从板读取，旧板缺失时由持笔补齐并告知用户。用户指定名、已派名及运行中的旧名保留。标题成功后同步案头、板上本案持笔镜像及当前载体；工具失败报告 UI 未同步，保留真实名称，不填拟定名冒充已设名。简短复述总目标、本案目标、进展/缺口和下一步。有数报数，案里没有就直说。用户要求继续且不缺必要输入时推进；仅用户要求抽查或真正阻塞才等。

后续仍按决策当场入 C、方案变化入 B、结果验收入 E 的节奏维护。
