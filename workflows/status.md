# 查看协作现状

先按 [共用方法](../docs/METHOD.md) 定位项目。此流程默认只读，不顺手抢持笔、改名、归档或重写案。

- 读板的目标与完整案索引，再按 [案生命周期](../docs/METHOD.md#案生命周期) 读取案头分类，不凭板上投影、文件排序或标题判断。默认展开活跃案的 A/B/D/E/H/I；已结案案不逐一复述历史。先覆盖案头、E、H 结案处置、I/离线来件所需的异常检查，再决定不展开，不能只因终态跳过收件。
- **筛选与统计同口径**：活跃案数、待推进、待接手、待拍板、在跑/待验收、未处理来件等正常汇总只计活跃案。结案中单列“收尾中”；已完成、已终止、已合并等终态不进入活跃总数或待接手列表。状态未知/冲突或案文件缺失单列待核实，不计成已结束，也不以全库总数冒充活跃数。
- **收尾异常单列**：结案中或已结案案存在在跑执行、未处置来件、未被接收的转交、残留持笔、未安置待办或案/板冲突时，给案号、具体事项和下一步。旧的 D/H 文本若已有对应结案处置“停止跟进/已转交”，不是活跃待办；结案之后新增的未处置来件不能被旧处置记录覆盖。不因发现异常自动重开案。查询结果按“活跃 / 收尾及异常 / 状态待核实”分别计数，避免混算或重复计算。
- 对转交处置，核对所指目标任务/消息及接收证据。只写了 ACK 标识或“已转交”、目标却缺对应记录，或证据不可读/互相矛盾时，明确列入“收尾异常：转交证据待核实”；不能仅凭原案自称已接收就过滤掉。读取超出授权或工具不可用时标未核实，不冒称核验通过。
- 用户要求“包括历史案”时，再展示终态案的结案类型、时间、原因与替代/承接案；用户点名一个已结束案时直接回答该案，不能因默认过滤而说未找到。问“哪些旧案可以结束”只给有证据的候选和未决影响，不自动结案。
- 检查对应 `inbox/<案ID>/` 是否有未合并来件，与 I 按消息 ID 去重。非本案持笔只报告，不改其 I；当前持笔获得维护授权后可按收件流程整合。
- 平台可查询时，按准确会话 ID 获取实时运行状态；案状态、运行状态、更新时间分别说明，不把“空闲”当“任务完成”。
- 任期从案头读取；板上的持笔名称是案头镜像，冲突时报告来源，不自动重编号。旧格式名称保留，查询会话不用于取号。
- 数字从当前证据取，无数据写未知。板、案、平台互相冲突时并列指出，不能静默选一边。
- 完成的执行任务还要确认交付已回收、判定写进 E、对方案的影响已处理。收到通知不等于验收完成。

面向用户简短汇报：总目标与当前阶段；活跃案及持笔；在跑/待验收；未处理来件与待拍板；存在时单列收尾异常/待核实状态。没有活跃案就如实说没有，不能因此省略仍存在的收尾异常。历史按需展开，默认不列每个已结案案。
