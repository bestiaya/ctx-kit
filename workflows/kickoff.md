# 开工与任务分诊

执行前读 [共用方法](../docs/METHOD.md) 和本平台规则。只处理当前已授权的项目与任务。

1. 确定项目边界和案库，说明首次写入的绝对路径。查任务板和案头，已有同目标的活跃案才考虑复用；“同项目/相关主题”不等于同一个可由同一方案结清的工作。用户明确独立组织的持续修复可单独建案并关联原案，不为凑编号新建重复案。不把安装目录当工作目录，不用 Git 顶层强行覆盖子项目归属。
   按 [案生命周期](../docs/METHOD.md#案生命周期) 识别终态。已结案案只作历史参考，不自动合并新工作或沿用其持笔；明确恢复原案时走 [恢复流程](case-lifecycle.md#恢复)，保持原案号。若当前请求实际是“这个案不用了/终止/合并”，直接转同一文档的结案分支；候选整理保持只读。案号占用检查仍包含终态案，不能回收其号码。
2. 多轮设计/实验/协作建案；明确的一次执行挂已有案的 E 或任务板独立任务；顺手改直接做，不机械扩大工作范围。
3. 新案按 [CASE](../templates/CASE.md) 建，案号只在本案库分配并防止同号覆盖，初始 `任期：01`。在板的名称列固定案短名；无案散活先登记板上行号。目标只写用户已表达内容，补充理解标“建议/待确认”；不擅自写死指标、期限、结论。
4. 认领前检查现有持笔；已有其他持笔时按交接规则处理。复用已有案但尚非其现任持笔时，正式认领走 [接手流程](takeover.md)，不把新案的 01 写入旧案，也不跳过任期递增。当前身份可用则记录平台+完整 ID；无法取得时如实记录临时身份和限制。
5. 按 [共用方法的会话命名](../docs/METHOD.md#会话命名) 从案头任期或散活登记行号确定名称，再通过平台工具设置；禁止为取号查会话列表。用户提供的工作描述不是指定完整标题，不能直接原样设名而漏掉编号。重复开工复用任期，明确指定的完整标题与运行中的旧名按兼容规则保留；用户仅要求改名时不建案。改名成功后同步案头、板的本案持笔镜像及当前载体；改名与案认领分别核验，失败写实际状态。把案链接放进 [TASKBOARD](../templates/TASKBOARD.md)，状态仍以案为准。关联他人案只送收件，不取得其任期或子号。
6. 本会话继续就直接推进；用户授权派活时，用 [TASK](../templates/TASK.md) 写自足任务书，在 E 登记载体与输出。派发者依据自己的已派记录分配子号，写入完整派定名；执行者沿用，只有实际派出的执行会话使用 `-exec`。收到实际会话 ID/标题后由持笔回填载体。创建聊天、发消息、派子代理分别遵守平台能力和已有授权；没有实际派出就只报“任务书已准备”。

回复目标、当前判断/关键未决、案路径和下一步即可。边讨论边更新 B/C/D，不等收口才补记录。
