# 收口、交接与结案

先读 [共用方法](../docs/METHOD.md) 和平台交接差异。普通交接留下可继续的状态，结案结束本案的推进，两者分别处理。

先判断用户要继续工作还是结束案：“这个案不用了/废弃/终止/做完了结案/并入另一案”等按 [案的结案与恢复](case-lifecycle.md) 执行，完成后停止本交接分支，不写候接手、不要求另开聊天。查看可终止候选走 [状态查询](status.md)，不执行结案。下列步骤仅用于工作还要继续的交接。

1. 按用户给出的案路径或当前已认领关系定位。独立执行任务交接其任务书、交付和未完成项，不代关联案释放持笔。无案散活沿用板上登记号；确需新建案时走 [开工流程](kickoff.md)，同时初始化任期、短名和板索引，不扫描其他项目认领相似名字。以下案内步骤仅由本案持笔执行。
   先读案头终态。已结案案不因交接调用变回候接手；说明已结束，只有明确恢复工作才走恢复分支。结案中的案先继续已登记的收尾，不把它当普通交接。
2. 确认本会话持笔。若持笔属于别人，不能代其释放；先核实授权/转交。若本会话已交出、此次仅重试 UI 标记，核验已保存的交接/释放证据后直接执行第 7 步，不重复释放，不覆盖继任。正常交接先在本次交接记录中保存交出会话的平台、完整 ID、原标题与任期，再写入 `交接: 收口中`，保留持笔。
3. 保存产物，产品事实写回已有事实源；更新 B 当前位置、下一步、继任阅读表（每件写路径或节——到节、事项 ID 或行范围、字符数、读取时机、要回答什么；表末写“开工前”合计，并以案头字符数＋方法规则＋该合计估出预计接手总量）与有效约束；决策及否决理由追加到决策记录；整理 D，已解决行删除并写去向；回收可用交付，已验收任务移入实验记录，已处理来件移入过程记录，编年写过程记录。仍在跑的任务写清载体、输出位置、当前状态、由谁回收。
4. 核对 G 指针；无法确认的转录路径写未知，不靠 `ls -t`、mtime 或相似标题猜。逐项读 H 缺口、I 收件和未合并 inbox，保存未完成、未验证及无法恢复内容；不能默默删除。
5. 检查案头、记录文件与必读片段可读、关键路径实际存在；以 Unicode 字符计案头，超 15,000 先把已结内容移入记录文件，移后仍超线在交接回执写明剩余字符数与原因，不删未解决事项；预计接手总量超 30,000 时在交接回执写原因与缩减办法（改“做到某事时”、只列节或行范围、交子代理摘要），首个动作必需的依据不因凑数改标；核对 inbox 的消息 ID 全部登记。只能提供部分交接时明确标注缺口；如果关键状态尚无法保存，保留收口中并说明阻塞，不宣称已可接手。
6. 最后记录前任身份，清当前持笔，设 `交接: 候接手`，更新带时区时间与 F；同步板上本案持笔镜像并回读核验。保留案头任期供下一任读取，不在收口时递增或清零。旧案没有任期字段时不倒查历史补数，留待正式接手初始化。旧单字段案保持兼容语义。释放未成功则停止在此处，不提前标记。
7. 按[共用退役标记规则](../docs/METHOD.md#交接后的会话退役标记)和平台可用能力，**必须**给本次交出的旧会话原标题加一次 `✕ `；已有前缀不再加。记录实际工具结果、可用的回读证据、案头字符数及预计接手总量到独立交接回执。能力缺失或失败时分别报告“文件交接/释放已完成”和“UI 标记未完成”，不回滚释放、不要求额外批准，也不修改继任案头或持笔镜像。
8. 按当前授权处理提交/推送；只提交本轮相关路径，不把其他会话未完成工作一起加入。没有授权就不把发布当交接前提。不会因交接自动删除、归档或关闭聊天、终止执行或创建新聊天。

回复：案绝对路径、当前状态、H 缺口与未处理来件、下一步，以及可复制的“接手该绝对路径”提示；分别说明文件交接/释放和旧会话 UI 标记的实际结果。不要再贴整份方案。
