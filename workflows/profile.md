# ctx-profile 共用流程

管理个人配置、手动历史议题和全局关键事项。核心论断、精彩表达及个人想法摘录使用 [独立知识条目流程](profile-insights.md)，不写入本页旧 `topic` 动作的 TOPICS.md。只读与写入按用户意图区分；只读查询不隐含保存授权。显式动作优先，再识别明确自然语言意图，无动作默认 `show`。

七个动作是 agent 的内部分类；用户直接用自然语言表达即可，无需说出技能名或动作名。只有明确要求保存时才写入长期内容。

## 入口与边界

正式目录默认 `~/.context-kit/`；用户指定测试根目录时，所有主档读写使用该目录。脚本的 `--root PATH` 明确根目录，路径相对调用者 cwd，技能与脚本链接相对技能文件解析。使用环境中可工作的明确 Python 解释器；下面 `<tool>`、`<history>` 是技能入口链接所指脚本的绝对路径。

只按当前动作读取下文对应一节，不把所有话题、事项或原生日志常驻加载。个人配置为 `CONTEXT.md`、`SPEC.md`、`TOOLS.md`；`TOPICS.md` 保存议题和历史读取方法；`global-task/BOARD.md` 保存用户明确要求记录的关键事项；`config.json` 只登记必要路径和接入状态。

个人配置不复制项目状态，议题不承担进度管理；全局事项可引用项目入口，项目任务树仍由项目板、案维护。旧历史查询不新增公共日志索引、后台采集、来源数据库或额外议题文件；用户明确保存的知识条目按独立流程维护。工具包和安装包不携带用户主档、正式配置、案文件或本机个人路径。

`init`、`update`、`adapt` 及 topic/task 的保存先返回预览，带 `--apply` 才写入。已有明确授权且范围一致就执行，不再询问；仅讨论、查看或查询时不加 `--apply`。预览不能写成已经完成。用户未指定同步全部平台时，adapt 只选当前明确的平台，不自动恢复已清理的 Claude 配置、缓存、登录或安装。

## show · 查看（默认）

运行 `python3 <tool> --root <root> show`，不写文件。查看当前主档内容及登记的接入情况；只读取用户本次需要的文件。不存在的根目录报告尚未初始化，不为查看自动 init。

区分文件已生成、入口已配置和原生客户端已验证。`configured_unverified` 不等于实际加载；脚本本身不能把 `native_load_verified` 宣称为 true。查看 topic/task 使用对应只读动作，不必载入其全文到个人配置。

## init · 建立主档

读取用户选定资料，整理出当前可采用的个人信息、长期习惯及工具约定，分别形成 `CONTEXT.md`、`SPEC.md`、`TOOLS.md`。源目录还需 `TOPICS.md` 和 `global-task/BOARD.md`：保留明确选定的既有内容，否则创建空结构，不自动登记话题或事项。候选资料放在用户指定或临时目录，不复制历史项目板、案、敏感缓存或账户凭据。

init 只补缺失文件，保留已有正式文档；读取发现需要修改的既有主档时，按 update 合并，不凭旧快照覆盖当前结论。初始 config 只建立空登记，不迁入旧快照中的“已生效”状态。最小接入链路为：准备选定源文件 → init 预览/写入 → 核对实际客户端入口 → 按下节用 adapt `--entry` 登记单个平台并接入 → 真实客户端验证。客户端目录必须已经存在，不为此重建已清理环境。

运行 `python3 <tool> --root <root> init --source <candidate-dir>` 查看范围；范围已获授权后加 `--apply`。只建立主档和必要空结构，不自动 adapt、安装技能或调用其他模型。普通提及的话题和本次画像工作不自动写入 TOPICS 或关键事项。

## update · 修改长期配置

“以后都按这个习惯，记下来”属于长期修改；当次要求或方案讨论不自动迁入。按内容选择 `CONTEXT.md`、`SPEC.md` 或 `TOOLS.md`，读取当前完整文件并计算 SHA-256，将本次修改合入候选完整文本，替换旧表述。重大调整可按需记录简短 ADR，不建设逐条来源台账。

运行 `python3 <tool> --root <root> update --file <CONTEXT.md|SPEC.md|TOOLS.md> --from <merged-file> --expect-sha <current-sha>`；已获授权后加 `--apply`。哈希漂移时重新读取并合并，不绕过保护。

update 自动同步 config 中已适配（含 `configured_unverified`）平台的生成内容。预览时说明实际涉及的平台和入口；读取当前登记状态，不把未适配的平台带入范围。保留生成块之外的原指令，重复同步不重复追加。同步完成只证明写入及幂等结果；原生加载验证另行记录。

## adapt · 接入指定平台

读取主档、SPEC 和当前平台适用的 TOOLS；核对 config 中实际路径和当前客户端真正使用的入口。用户明确选择 `codex`、`claude_code` 或 `all`，再运行 `python3 <tool> --root <root> adapt --agent <agent>` 预览；授权范围一致时加 `--apply`。

首次登记或明确变更入口时，用 `adapt --agent <codex|claude_code> --entry <absolute-entry-path>`。`--entry` 只适用于单个平台；核对是真实生效入口且其父目录已存在，再纳入预览与已授权的写入。`all` 只处理已登记平台，不自动发现或登记其他平台。

adapt 会登记当前主档工具同目录中实际存在的 `profile_history.py` 路径，保留 config 的其他字段和历史 roots；不存在就不登记虚构脚本。搬移已安装技能后，需要重新核对已登记脚本路径。日志目录仍以已核实的 config 登记为准，不因技能存在就声称历史适配完成。

格式、路径、引用和平台表达可以调整，个人事实与偏好的含义一致。保留入口中其他指令，更新既有生成块；不重复追加、不重建已清理的客户端环境。当前读取成功、生成文件或 CLI 返回成功均不足以证明原生加载。

真实客户端验证时，确认新会话从实际入口读到本次主档内容，保留平台、时间和验证证据，再按正式配置的验证记录机制登记。未验证如实报告 `configured_unverified`；脚本不代替客户端验证，不自行改为 `native_load_verified: true`。

## export · 给其他 agent 使用

运行 `python3 <tool> --root <root> export` 合成画像、SPEC 和适用工具约定，可用 `--agent <agent>` 指定平台。默认不带议题、看板或项目内容。返回文本无需改主档或接入状态。

用户明确要求文件导出时使用 `--output <path>`，先说明输出路径和内容范围；已有授权直接执行。导出不是安装、adapt 或真实加载验证，不在导出中声称全局生效。

## topic · 保存或查询历史议题

明确“增加话题”“保存当前讨论为话题”“更新话题 X”才写入。多个无关主题且无法识别保存目标时，只补问必要信息；查看或“查一下之前讨论过的”始终只读。

只读运行 `python3 <tool> --root <root> topic`，按请求查 `TOPICS.md`。有出处先定点读原文；未命中或不足再按 config 登记的方法查对应平台原生记录，不扫描无关账户材料。专用脚本为 `python3 <history> --config <root>/config.json --agent <codex|claude_code>`，按需限定 `--session <id>`、`--project <path>`、`--query <text>`、`--limit <n>`、`--date-from <date>`、`--date-to <date>`。根目录中的登记路径决定读取范围，不硬编码本机目录；没有 topic 也可以查历史。

返回相关原文、时间、会话及原位置，区分讨论、实际调用和产出；记录缺失、未适配或不可读时说明覆盖范围，不把“未找到”写成“从未发生”。查询结果不自动保存。

保存时读取当前 TOPICS 全文，计算 SHA-256，合并标题、更新时间、必要背景、当前结论、未决事项和出处；同一议题更新原摘要，保留原有议题及历史读取说明。运行 `python3 <tool> --root <root> topic --from <merged-topics-file> --expect-sha <current-sha>` 预览，明确保存授权下加 `--apply`。漂移时重读合并。

## task · 手动关键事项

明确新增、更新、完成或查看请求才处理；普通提及不写入。只读运行 `python3 <tool> --root <root> task`，读取 `global-task/BOARD.md`。

保存时读取当前完整看板并计算 SHA-256，合并事项、状态、简短下一步、更新时间和相关入口。状态使用待办、进行中、已完成；不复制项目任务树，不把议题摘要当事项。运行 `python3 <tool> --root <root> task --from <merged-board-file> --expect-sha <current-sha>` 预览，明确授权后加 `--apply`；漂移重读合并。

## 结果说明

简明报告本次动作、实际文件/入口、预览或已写入、验证结果与未完成项。历史查询给必要出处；配置同步给实际平台及加载验证状态。实现或打包任务不自动授权安装、提交、推送或修改个人正式运行目录。
