# 协作与上下文审核

先读 [共用方法](../docs/METHOD.md) 和平台证据。默认只读检查；用户要求出报告时，按 [AUDIT](../templates/AUDIT.md) 保存到目标项目约定的审核目录。

## 协作一致性

- 使用当前真实时间与时区，明确检查范围和采样时点。
- 检查板的索引、案的持笔与交接状态、E 中载体与交付路径、H 缺口、I 和未合并 inbox。
- 依 [案生命周期](../docs/METHOD.md#案生命周期) 审核全部被纳入范围的案，包括终态，不能沿用 status 默认不展开历史而跳过它们。核对结案类型/时间/原因、关联案、处置去向、持笔释放及板投影；旧 closed 缺字段标兼容缺口，不虚构完成。已结案却还在跑、候接手、待转交或有未处置来件/待办，报告收尾异常，查证而不自动重开。明确停止跟进的历史缺口不算漏办；案文件缺失不算已终止。
- 核对 status 的筛选与统计口径：活跃、结案中、终态、状态待核实应区分；终态的收尾异常必须可见，历史展示不应改变活跃统计。检查重复结案未改结束时点/任期，恢复保留原案号与结案历史、仅正式认领加一次任期，转交或已拒来件未被自动重启。
- 命名核验使用案头任期、板的案短名/散活行号和已派子号；核对 UI、案头及板上持笔镜像是否一致。旧名和缺任期的旧案按共用兼容规则报告，不因格式不同认定孤儿，不扫描会话列表分配号码。
- 查询可用平台状态作交叉验证。区分“记录未更新”“运行状态未知”“明确已结束”，不凭时间戳判死会话。
- 检查在跑、待验收、已完成之间的证据：任务产物存在不等于验收通过；缺失证据不能自动补成通过。
- 报告冲突、失效指针、未处理来件、长期未回收交付。给具体案/任务/来件 ID，建议由谁处理。不自动清理或抢占。

## 经济与质量

按平台 EVIDENCE 分开两项。先使用已有真实复杂任务记录；新增对照运行须遵循用户允许的范围，不为测量擅自发保温请求或产生大量额外调用。

1. 经济：区分本次输入、缓存命中、累计用量、压缩、子任务、交接生成、接手补读及返工。只在有请求级口径时计算命中率；看不到费用/订阅映射就只报可观测量。不能把 API 价格直接套订阅额度。
2. 质量：固定模型/配置，记录实际可用窗口、当前占用和任务阶段；核验约束、事实召回、推理与交付结果。长度、难度、过时方案和整理效果分别考虑，不把后半程更难归因于“过半变笨”。

输出“已证实 / 仅支持方向 / 不支持 / 判不出”，附范围、样本、来源、反例和下一次需要的数据。候选阈值保持待验证，不能因一次通过自动升级为全局强制规则。
